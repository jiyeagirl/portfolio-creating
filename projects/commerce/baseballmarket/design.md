# BaseballMarket — Design

야구 팬덤 중고거래 플랫폼. 사용자 웹 콘솔 + 관리자 웹 콘솔(별도 URL).

## 아키타입

- **관리자 셸: C4 — 아이콘 레일 + 섹션 리스트 (3-column).** spec의 관리자 IA가 2단계다.
  최상위 4섹션(운영 대시보드 / 매물·티켓 / 회원·거래 / 커뮤니티·신고) 아래에 하위 뷰가
  15개 있다(매물 조회, 카테고리·구단 마스터, 금지품목 키워드, 티켓 정가 기준표,
  정가초과 자동탐지, 신고 매물, 회원 조회, 거래 이력, 제재 이력, 정산, 분쟁·환불,
  게시글·댓글, 신고 분류, 금칙어, 공지·문의). 2단계를 표현할 셸이 필요했다.
- **배제 1 — C1(다크 레일 콘솔)**: 두 가지 이유로 불가. ① `projects/commerce/` 안에서
  pawfit-admin과 snowpeak-admin이 이미 C1이다(같은 카테고리 중복 금지).
  ② 236px 레일 하나에 15개 뷰를 평면 나열하면 스캔이 무너진다.
- **배제 2 — C3(상단 커맨드 바)**: 수평 주내비 상한이 5개라 2단계 IA를 담을 자리가 없다.
  C3는 하루 종일 한 큐에 머무는 콘솔용인데, 이 관리자는 대시보드 / 마스터 데이터 관리 /
  정산 / 신고 처리를 오가므로 "한 화면에서 끝"이 아니다.
- **이 셸에서 쓰지 않는 부품**: 236px 라벨 레일, 전폭 `h-14` 헤더(헤더는 본문 컬럼 위에만
  얹힌다), `fixed inset-0 z-50 lg:hidden` + 264px 드로어, `max-w-[1400px]`, 헤더 우측 시계.
- **홈 아키타입(A1~A8) 없음.** 웹 전용 프로젝트다. 사용자 콘솔은 vercel_compact이 규정한
  상단 내비(64px) + 1280px 콘텐츠 + 캔버스 푸터 구조를 쓴다. 모바일 앱을 추가하게 되면
  그때 `-mobile` 별도 프로젝트로 만들고 A번호를 배정한다.

## 적용 규칙

- `spec.md` `디자인시스템: vercel_compact` → `design-systems/vercel_compact.md`가 색·타입·
  컴포넌트 스펙의 최우선 출처(CLAUDE.md Precedence 2단계).
- `spec.md` `스타일: high-end-visual-design` → 모션 안무, 마이크로 인터랙션, 여백 리듬을 맡는다.
- **충돌 해소(전부 vercel 우선)**: 스킬은 "떠 있는 글래스 필 내비 + `backdrop-blur-3xl`
  오버레이 / `rounded-[2rem]` / 확산 앰비언트 그림자"를 요구하지만 vercel은 nav-bar를
  캔버스 64px로, radius 상한을 16px로, 그림자를 **미세 다층 스택**으로 규정한다.
  vercel을 따른다. 스킬에서 실제로 가져온 것은 아이브로우 태그, 버튼 안 원형 아이콘 래퍼,
  스태거 진입, 커스텀 이징이다.
- 스킬이 금지한 Geist는 CLAUDE.md 규칙(항상 Pretendard)이 이미 대체한다. vercel 문서도
  같은 대체를 명시하고 있다.
- `DESIGN_VARIANCE 7 / MOTION_INTENSITY 3 / VISUAL_DENSITY 7`
  (관리자 표는 밀도 8로 국소 상향).

> **이전 이력**: 처음에는 `clay_compact`(크림 캔버스, 6색 순환, 그림자 0개)로 만들었다가
> 사용자 요청으로 `vercel_compact`으로 전면 교체했다. 두 시스템은 거의 모든 축이 반대라
> 토큰 값, 그림자 정책, radius 사다리, 눌림 피드백, 카테고리 타일이 전부 바뀌었다.
> CSS 변수 **이름**은 유지했다 — 화면 코드가 90곳 넘게 참조하고 있어 이름을 바꾸면
> 의미 없는 대량 치환이 생긴다.

## Tokens / 팔레트

**팔레트 구성 5 — 하이컨트라스트 / 무액센트.** 잉크와 종이 두 색 + 상태색만 쓰고,
강조는 크기와 굵기로 한다. vercel의 "액센트는 primary(잉크 블랙) 하나만"이 이 구성의
정의와 그대로 맞는다. `projects/commerce/` 안에서 처음이다(verve는 다크 우선).

| 역할 | 변수 | 값 |
| --- | --- | --- |
| 캔버스 | `--bm-canvas` | `#ffffff` |
| 표면 1 | `--bm-surface` | `#fafafa` |
| 표면 2 | `--bm-surface-card` | `#f5f5f5` |
| 표면 3 | `--bm-surface-strong` | `#ebebeb` |
| 헤어라인 | `--bm-hairline` | `#ebebeb` |
| 헤어라인 강 | `--bm-hairline-strong` | `#d4d4d4` |
| 잉크 (= 유일한 액센트) | `--bm-ink` | `#171717` |
| 본문 강 / 본문 / 보조 / 보조 약 | `--bm-body-strong` `--bm-body` `--bm-muted` `--bm-muted-soft` | `#2e2e2e` `#4d4d4d` `#666666` `#888888` |
| 링크 | `--bm-link` `--bm-link-deep` `--bm-link-soft` | `#0070f3` `#0761d1` `#d3e5ff` |
| 성공 | `--bm-success` | `#0070f3` (vercel은 성공이 그린이 아니라 링크 블루다) |
| 주의 | `--bm-warning` `--bm-warning-deep` | `#f5a623` `#ab570a` |
| 오류 | `--bm-error` `--bm-error-deep` | `#ee0000` `#c50000` |

**브랜드 메시 그라데이션 3쌍**(`--bm-mesh-a/b/c`)은 vercel 규칙대로 **히어로 스케일에서만**
쓴다. 아이콘 크기로 축소하거나 단색으로 자르지 않는다. 사용처는 페이지 전체에서 **두 곳뿐**:
홈 헤드라인의 "홈경기" 텍스트 클립, 그리고 잉크 카드 상단의 3px 라인.

**액센트 운용 — 구단 색은 없다.** spec 3.1의 "구단 테마가 반영된 홈"을 색으로 구현하면
"액센트는 잉크 하나"라는 vercel 규칙이 깨진다. 대신 **내 응원 구단만 다크 반전 밴드**를
갖는다 — 홈에서 잉크 배경 카드를 갖는 요소는 오늘의 경기 카드 하나뿐이고, 나머지 구단은
잉크 사각 모노그램(`TeamMark`)으로만 표기된다. 표면 순환도 vercel이 규정한
`canvas-soft → canvas → ink(다크 반전)` 밴드 순서를 따른다.

구단명은 전부 가상이다(서울 그라이더스, 인천 하버스, 대전 코메츠 등). 지역명만 실제이고
팀명·선수명·등번호는 실재하지 않는 값이다.

## Shape

- radius 사다리: `4 / 6 / 8 / 12 / 16 / pill`. **상한 16px.** 스킬의 `rounded-[2rem]`(32px)은
  쓰지 않는다. 티어 배정은 버튼·입력·칩 6, 카드·표·패널 8, 큰 표면 12, 히어로 16이다.
- **pill 스케일 두 가지를 한 화면에서 섞지 않는다**(vercel 규칙). 마케팅 표면(홈 히어로)은
  `Button variant="cta"`의 pill을 쓰고, 앱·관리자 표면은 전부 6px을 쓴다.
- **그림자 정책: 미세 다층 스택 + inset hairline.** `--bm-shadow-1`(2겹) /
  `--bm-shadow-2`(4겹) / `--bm-shadow-hairline`을 조합하고, 단일 두꺼운 drop-shadow는
  쓰지 않는다. 각 레이어 알파는 0.02다.

## Typography

Pretendard 고정. 웨이트 **천장 600** — 700 이상을 쓰지 않는다(vercel 규칙).

| 역할 | 값 |
| --- | --- |
| Display | 48/48, 600, `-0.05em` (모바일 32/40, `-0.04em`) |
| Heading | 32/40 600 `-0.04em` · 24/32 600 `-0.04em` · 20/28 600 `-0.03em` |
| Body lg | 18/28, 400 |
| **Body** | **16/24, 400** |
| Body sm | **14/20, 400, `-0.01em`** (앱·관리자 밀집 UI의 기본) |
| Caption | 12/16, 400 |
| Mono | 숫자·기호 전용 |

- 헤드라인은 문장체이고 마침표로 끝나며 강한 음수 letter-spacing을 갖는다(vercel 규칙).
- **모노스페이스는 한글에 쓰지 않는다.** vercel은 "섹션 eyebrow는 항상 모노"라고 규정하지만
  그 규칙은 라틴 문자를 전제한다. 한글을 라틴 모노에 넣으면 폰트가 없어 시스템 폰트로
  폴백하면서 글자마다 폭이 강제되고 `대전  코메츠  팬  홈`처럼 자간이 벌어진다.
  실제로 그렇게 렌더된 것을 스크린샷에서 확인하고 되돌렸다. 모노는 `MonoIndex`(01~06),
  시각, 차트 축, 단위 접미사에만 남겼다. "본문은 절대 모노 금지"라는 vercel 규칙과도 맞는다.
- **스케일 복제 금지 — 앞선 프로젝트와 다르게 한 것**: 본문 쌍은 **14/20 + `-0.01em`**이다.
  워크스페이스 13개가 쓰는 `15/22`도, 직전 재설계 veli의 `16/24`도 아니다. 결정적인 차이는
  **음수 letter-spacing을 본문에 넣은 프로젝트가 여기뿐**이라는 점이다. 숫자 자체는
  `spec.md`가 지목한 디자인 시스템이 규정한 값이라, 다른 프로젝트의 임의 선택을 베낀
  "스케일 복제"와는 다르다.

## 셸 레이아웃

**사용자 콘솔** — vercel이 규정한 사이트 셸. 관리자 셸(C1~C4)과 다른 축이다.

| 항목 | 값 |
| --- | --- |
| 상단 내비 | 64px, `sticky top-0 z-30`, `bg-[var(--bm-canvas)]` + `border-b`. **`backdrop-blur` 없음** |
| 콘텐츠 max-width | `mx-auto max-w-[1280px]` |
| 본문 패딩 | `px-5 py-10` → `lg:px-8 lg:py-14` |
| 섹션 간격 | 96px |
| 푸터 | 캔버스(흰색) + 상단 헤어라인, 4컬럼. **다크 푸터 금지** |
| 모바일 | < 768 단일 컬럼, 내비는 인라인 불투명 패널(글래스 아님) |

**관리자 콘솔 — C4**

| 항목 | 값 |
| --- | --- |
| 아이콘 레일 | `w-16`(64px) `sticky top-0 h-dvh`, 라벨 없음, 활성 섹션만 `--bm-surface-strong` 필 |
| 섹션 리스트 | `w-[232px]`, 현재 섹션 제목 + 하위 뷰 목록 + **섹션 고유 요약 블록** |
| 헤더 | 56px, **본문 컬럼 위에만** 얹힌다(레일·섹션 리스트를 가로지르지 않음) |
| 본문 max-width | `max-w-[1180px]` |
| `lg:` 분기 | `lg:` 미만에서 레일은 하단 아이콘 바, 섹션 리스트는 가로스크롤 세그먼트. **드로어 없음** |
| 시계 | 없음 |

섹션 리스트의 요약 블록은 섹션마다 다른 값을 쓴다 — 매물은 `자동탐지 대기`, 회원은
`분쟁 진행`, 커뮤니티는 `신고 미처리`. C4가 "C1 레일을 둘로 쪼갠 것"으로 퇴화하지 않게 하는
장치다(`ARCHETYPES.md` C4 주의 항목).

## 표 밀도 / 컬럼 예산

`Table`은 `overflow-x-auto` 안에 있어 **컬럼 폭 합이 넘치면 마지막 열이 조용히 잘린다.**
C4는 표 옆에 디테일 패널이 서기 때문에 **예산이 두 개**다.

| 상황 | 가용폭 | `minWidth` | 열 상한 |
| --- | --- | --- | --- |
| 패널 없는 표 | 1440 − 레일 64 − 섹션 232 − 패딩 64 = **1080** | 940 | 6 |
| **패널과 나란한 표** | 위에서 패널 360과 간격 20을 더 뺀 **700** | **640** | **5** |

- 마스터-디테일 5개 화면(매물 조회, 정가 초과 탐지, 회원 조회, 분쟁, 신고 처리)이
  아래쪽 예산을 쓴다. 넘치는 값은 지우지 않고 **셀 안 보조 줄로 내린다**:
  매물+판매자, 구단+시즌, 구장+구역, 정가+판매가, 신청자+상대, 대상+유형.
- **이 계산은 처음에 틀렸다.** 940/1040으로 잡고 패널 폭을 빼지 않아 정가 초과 탐지 표의
  판매가, 초과율, 상태 세 열이 실제로 잘려 나갔다. 스크린샷으로 확인하고 고쳤다.
  표를 새로 추가할 때 패널 유무를 먼저 보고 예산을 고른다.
- 좌우 높이가 다른 그리드에는 `items-start`.

## Motion

| 대상 | 값 |
| --- | --- |
| 진입 (섹션/카드) | **210ms `cubic-bezier(0.4, 0.14, 0.3, 1)`** + `translateY(6px)` → 0 |
| 스태거 간격 | 40ms |
| 탭/필터/색 전환 | 120ms, 같은 이징 |
| **프레스 피드백** | **그림자가 무너진다.** 다층 스택 → inset hairline만, 90ms |
| 표 행 hover | 배경만 한 단계 |

- **스케일 복제 금지 — 앞선 프로젝트와 다르게 한 것**: 이징
  `cubic-bezier(0.4, 0.14, 0.3, 1)`은 워크스페이스 미사용 값이고, 진입 거리 6px과
  duration 210ms도 어디에도 없다. 번져 있는 `420ms cubic-bezier(.16,1,.3,1)`(CSS 11개)과
  방향이 다르다 — expo-out은 길고 부드럽게 미끄러지는데 이건 짧고 즉각적이다.
  clay 시절 쓰던 680ms / 18px도 함께 버렸다. spring `{stiffness:300, damping:30}`은 쓰지 않는다.
- **프레스도 워크스페이스 어디와도 다르다**: veli는 `translate-y`, 다수는 `active:scale-95`,
  clay 시절 이 프로젝트는 표면 색 한 단계였다. 지금은 **그림자가 무너진다** — vercel이
  깊이를 그림자로 표현하므로 눌림도 그림자로 표현하는 것이 일관된 귀결이고, transform을
  전혀 쓰지 않는다.
- `prefers-reduced-motion: reduce`에서 진입 애니메이션과 스태거, 전환을 모두 끈다.

## 관리자 분리

관리자 콘솔은 `/commerce/baseballmarket-admin`으로 **URL과 로그인이 분리**되어 있다.
화면 코드는 이 프로젝트의 `components/admin/` 안에 있고 `-admin` 프로젝트는 엔트리만 갖는다
(`styles/`·`design.md` 없이 이 프로젝트의 토큰을 상속). 사용자 콘솔에는 관리자 진입점
(내비 항목, 로그인 역할 선택)을 두지 않는다.
