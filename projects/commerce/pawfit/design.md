# PAWFIT — Design Notes

## Design read

반려동물 보호자를 위한 맞춤 사이즈 추천형 반려동물 의류 자사몰. 소비자 대상
커머스 앱이라 클레이메이션풍의 따뜻하고 장난기 있는 브랜드 보이스를 쓰되,
사이즈 추천이라는 신뢰가 필요한 기능이 핵심이라 화려함이 신뢰를 해치지 않게
절제한다.

- **디자인시스템**: `clay_compact` — 크림 캔버스, 6색 브랜드 팔레트 로테이션,
  radius 문법(버튼/인풋 12px, 카드 16px, 히어로급 24px, 배지/탭 pill), 그림자 없음
  (색 대비로만 깊이 표현), 디스플레이 타이포 500 웨이트 고정이 최우선 출처.
- **스타일**: `high-end-visual-design` — 프리미엄 실행력(넉넉한 여백, 스프링
  물리 기반 트랜지션, 매그네틱 버튼 프레스 피드백, 스크롤 리빌)의 "느낌"만
  차용한다. 이 스킬의 리터럴 컴포넌트 규칙(더블베젤 중첩 그림자, 백드롭블러
  랜딩 히어로, 세리프/그로테스크 디스플레이 폰트)은 `clay_compact`의 "그림자
  없음" 규칙 및 워크스페이스의 Pretendard 고정 규칙과 정면으로 충돌하므로
  적용하지 않는다 — CLAUDE.md 우선순위 규칙대로 디자인시스템이 이긴다.
- **폰트 굵기**: `clay_compact`가 이 프로젝트의 유일한 굵기 규칙 출처다.
  디스플레이 500(`font-medium`) 고정, 타이틀 600(`font-semibold`), 본문
  400(`font-normal`). veli/apple_compact의 "500 금지" 규칙은 그 프로젝트에만
  적용되는 규칙이라 여기서는 적용하지 않는다.

Dials: `DESIGN_VARIANCE 6` / `MOTION_INTENSITY 5` / `VISUAL_DENSITY 5`
(커머스 앱이라 veli보다 밀도는 높지만, 사이즈 추천의 신뢰감을 위해 변주와
모션은 중간 수준에서 멈춘다.)

- 캔버스는 항상 크림. 버튼/CTA는 화려한 브랜드 컬러 대신 잉크 블랙 하나로
  고정 — `clay_compact`의 `button-primary` 스펙을 그대로 따른다. 브랜드
  6색은 카드 배경(반려동물 카테고리 칩, 상품 타일, 온보딩 배너)에서만
  순환시키고, 같은 색을 연속 배치하지 않는다.
- 그림자 없음. 깊이는 크림 캔버스와 채도 높은 카드의 색 대비로만 표현한다.
- 이 프로젝트는 라이트 전용이다(다크모드 미지원) — `clay_compact` 자체가
  크림 캔버스 하나의 팔레트만 정의하고 있고, filmate의 다크 전용 선례와
  마찬가지로 브랜드 정체성상 테마 전환이 필요 없다고 판단했다.

## Shape

- 카드 16px(`rounded-[16px]`), 히어로/온보딩처럼 화면을 지배하는 큰 배너만
  24px(`rounded-[24px]`). 버튼과 인풋은 12px(`rounded-[12px]`) — **pill이
  아니다**, `clay_compact`의 `button-primary` 스펙이 명시적으로 md(12px)를
  지정한다. 배지, 카테고리 탭, 사이즈 칩만 pill.
- 그림자 없음 원칙을 지킨다. 카드 구분은 `surface-card`/`surface-soft`
  색 블록 전환과 얇은 `hairline` 보더로만 한다.

## Typography

Pretendard 고정. 디스플레이(화면 타이틀, 추천 사이즈 결과 등) 500 웨이트 +
네거티브 트래킹, 타이틀(카드 제목) 600, 본문 400. 가격, 몸무게, 사이즈
수치는 `.pf-num`으로 tabular-nums를 강제한다.

## 사진 매핑

이 프로젝트는 실제 반려동물 사진이 화면 완성도에 꼭 필요한 커머스 앱이라
(veli와 달리) 사진을 적극적으로 쓴다. 이번엔 네트워크로 후보 이미지를 실제
내려받아 하나씩 확인할 수 있었다 — 이전 프로젝트에서 "네트워크 접근 불가"로
판단했던 건 `curl`에 리다이렉트 추적(`-L`)을 빠뜨린 내 쪽 오류였다(정정).

`picsum.photos`는 반려동물 사진 적중률이 낮아(대부분 풍경/건축/인물이라
견종·묘종을 골라 쓸 수 없음), 키워드 검색이 되고 `?lock=<n>`으로 같은
키워드에 대해 항상 같은 사진을 반환하는 `loremflickr.com`(Flickr Creative
Commons 사진, CLAUDE.md의 "고정 id" 원칙과 동일하게 키워드+lock 조합이
고정 id 역할)을 대신 썼다. 받은 사진은 전부 `assets/pets/`에 로컬 저장해
ES import로만 쓴다 — 런타임에 외부 서비스에 의존하지 않는다는 점에서
오히려 picsum 라이브 URL 방식보다 안전하다.

후보를 여러 장 내려받아 직접 확인한 뒤(예: "sweater" 키워드는 사람이 입은
크리스마스 스웨터 사진이 나와 반려동물 의류 화면에 걸면 완전히 어긋나는
사진이라 폐기, "dog" 일부 lock 값은 표지판 안내견/스쿠비두 코스튬처럼
무관한 사진이라 폐기), 실제 반려동물이 선명하게 나온 8장만 채택했다.

**상품(의류) 이미지 — 검증된 사진이 있는 카테고리만 실사, 나머지는 `ProductTile`.**
처음에는 "PawFit은 가상의 브랜드라 실제 제품 사진이 존재할 수 없다"는 이유로
전 상품에 `ProductTile`(브랜드 6색 로테이션 + 카테고리 아이콘 + 컬러웨이 스와치)만
썼다. 이후 사용자가 아이콘 대신 실사 사진을 요청해 카테고리별로 후보를 다시
찾았는데, `loremflickr`가 `harness`/`raincoat`/`bandana`/`boots`/`pajama`
같은 특정 키워드에서 지속적으로 500 에러를 반환해(재시도·대기 후에도 동일,
`dog`/`cat`/`puppy`/`kitten`/`sweater`처럼 이미 쓰던 키워드는 정상 작동 —
서비스 쪽 캐시/버그로 추정) 모든 카테고리를 사진으로 채우지 못했다.

`loremflickr`가 막힌 뒤로는 사용자가 직접 촬영/생성한 상품 사진 6장을 전달해
대부분의 공백을 채웠다. 각 파일은 사용자가 붙인 한글 파일명(예:
"강아지 매쉬에어하네스.png")으로 어떤 상품용인지 먼저 확인한 뒤, 사진 내용과
상품 설명이 실제로 맞는지 다시 한번 확인하고 연결했다(예: "강아지 반다나.png"는
사진상 니트 스웨터가 더 크게 보이지만 파일명이 명시한 의도대로 반다나 상품에
연결했고, 목에 두른 반다나가 깅엄 체크 패턴이라 하트 도트가 아닌 체크 반다나
세트 쪽에 매칭했다).

구조라 두 표현이 한 컴포넌트 안에서 공존한다.

## 기기 프레임 안쪽 규칙

하단 탭바, 상품 상세의 스티키 구매 바는 모두 불투명 배경(`--pf-surface-soft`
또는 `--pf-canvas` 고정값)을 쓴다. `backdrop-blur`는 쓰지 않는다 —
`PhoneFrame`의 `overflow-hidden` + `rounded-[50px]` 클리핑을 벗어나 기기
모서리 바깥으로 흰 테두리가 삐져나온다.

## Motion

- 화면 전환: 8px 상승 + 페이드 240ms, `cubic-bezier(.16,1,.3,1)`.
- 버튼 프레스: `active:scale-[0.97]` (매그네틱 프레스 피드백을 clay의
  그림자 없음 원칙 안에서 스케일만으로 표현).
- 사이즈 추천 결과가 나타날 때만 결과 카드에 240ms 스태거 페이드업 — 상태
  전달용 모션이고 장식이 아니다.
- 전부 `prefers-reduced-motion`에서 즉시 정지.

## 관리자 콘솔 — 별도 프로젝트로 분리

관리자 백오피스는 사용자 앱과 완전히 분리된 프로젝트 엔트리
`projects/commerce/pawfit-admin`(`/commerce/pawfit-admin`)을 갖는다. 실제
화면 코드는 이 프로젝트의 `components/admin/` 안에 있고,
`pawfit-admin/src/index.tsx`는 라우트 등록용 엔트리일 뿐이다(`lumi`/`veli`와
동일한 워크스페이스 관례). 사용자 앱 쪽에는 관리자 진입점을 두지 않는다.
`pawfit-admin` 프로젝트에는 `styles/`·자체 `design.md`를 두지 않고, 이
문서의 토큰을 그대로 상속한다.

같은 토큰을 쓰되 밀도를 올린다(`VISUAL_DENSITY 7`). 사이드바는 CLAUDE.md
웹 콘솔 구조 베이스라인대로 잉크 반전(다크) 대신, 이 워크스페이스의
"플랫폼" 카테고리 선례(lumi-admin, veli-admin)처럼 크림 상단 헤더 +
가로/세로 필 내비게이션으로 통일한다 — 별도 프로젝트로 완전히 분리된
소규모 운영 콘솔에서는 다크 레일보다 이 패턴이 이미 반복 검증됐다. 상품
관리 화면에도 사진 대신 `ProductTile` 컴포넌트를 재사용한다.

### 표 밀도 · 컬럼 예산

`Table`의 `minWidth` 900px 기준, 컬럼 상한 6-7열. 넘칠 것 같으면 보조
정보(등록일, 최근 활동)를 값 아래 보조 줄로 내리고 열 수를 줄인다.
