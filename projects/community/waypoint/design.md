# Waypoint — Design Documentation

## 아키타입

**A4 — 맵 캔버스 + 바텀시트** (`ARCHETYPES.md`). 관리자 셸 **C3(상단 커맨드 바)**,
팔레트 구성 **3(듀오톤)**.

`spec.md`의 Key Focus 첫 줄은 "'내 동선 홈'을 핵심 차별점으로 가장 강조"다. 그런데 이전
구현(A1 섹션 스택)에서 지도는 홈 화면 맨 아래의 **아무 동작도 없는 버튼 하나**로만
존재했다:

```tsx
<Button variant="secondary" full>지도 기반 동선 보기</Button>
```

제품의 핵심 차별점이 UI에 존재하지 않았다는 뜻이다. 게다가 홈 골격이 형제 프로젝트
`community/enclave`와 거의 같았다 — `ProductCard`가 radius 2px(`18px` vs `16px`,
`14px` vs `12px`)와 토큰 prefix만 달랐다.

A4로 바꾸면서 지도가 홈 전면이 되고, 매물은 지도 위 가격 핀으로 흩어진다. 목록은
3단 스냅 시트 안으로 들어갔다.

**배제한 후보 2개**

- **A1 유지** — enclave와 같은 골격을 두 개 두는 것이 이 워크스페이스의 문제 자체다.
  같은 카테고리(`community/`) 안에서 같은 아키타입 2개는 배정 규칙 위반이기도 하다.
- **A8(풀블리드 에디토리얼 캐러셀)** — 매물 사진이 좋아서 후보였으나, 중고거래는
  가격과 거리를 비교하는 행위다. 한 화면에 한 매물만 보이면 비교가 불가능하다.
  큐레이션 콘텐츠의 아키타입이지 마켓플레이스의 것이 아니다.

**enclave는 A1로 남긴다.** 스코프가 아파트 단지 하나라 반경 200m짜리 지도에는 정보가
없다. enclave에는 리스트가 맞다 — 나중에 차별화한다면 밀도와 타이포 쪽이지 골격이 아니다.

**이 아키타입에서 쓰지 않는 부품**

- **하단 탭바** — `components/bottom-nav.tsx` 삭제. 시트 헤더의 `SheetSegment`
  (내 동네 / 내 동선)가 그 역할을 하고, 나머지 화면은 시트에서 푸시된 뒤 좌상단
  뒤로가기로 지도에 복귀한다.
- **`SectionTitle`** — 홈에 섹션 반복이 없다. (다른 화면들이 아직 쓰므로 `ui.tsx`엔 남는다.)
- **`HeroCard`** — 지도 자체가 히어로다.
- **가로스크롤 카드 로우** — "최근 본 상품", "오늘의 추천 거래" 같은 캐러셀을 없앴다.
  지도 위 핀이 그 역할을 대신한다.
- **`pb-[110px]` 탭바 여백** — 탭바가 없으므로 `pb-10`.

**지도는 라이브러리 없이 SVG로 직접 그린다**(`components/map-canvas.tsx`) — 워크스페이스의
차트 규칙과 같은 원칙이다. 뷰박스는 PhoneFrame 화면과 같은 `393×852`라 어떤 시트 단계에서도
잘리거나 늘어나지 않는다. 동선과 핀은 `y 168~412` 구간에 모아 두었다: 시트가 `half`
(상단 426px)일 때 집과 직장 양 끝이 모두 보여야 듀오톤이 뜻을 갖기 때문이다.

핀 좌표는 `PIN_SLOTS` / `SPOT_SLOTS` 고정 표에서 온다. 매물 정렬 순서가 바뀌어도 지도가
흔들리지 않게 하려는 것이므로, 매물을 추가할 때 이 표도 같이 늘린다.

## 적용 규칙

- 스타일: `high-end-visual-design` (spec.md 지정) — Double-Bezel(아우터 셸+이너 코어) 카드 구조, 넉넉한 매크로 여백, 스프링 모션, 필-버튼 CTA를 웨이포인트 특유의 "신뢰/동선" 톤에 맞춰 적용. 폰트/기기프레임/8px 그리드는 워크스페이스 CLAUDE.md 규칙(Pretendard, iPhone 16 Pro, 단일 기기, 흰 배경)이 항상 우선.
- 디자인시스템: 미지정 — `design-systems/`는 참조하지 않음.
- `design-taste-frontend`(v2)는 배경 원칙으로만 참고(이 프로젝트는 랜딩이 아닌 모바일 프로덕트 UI라 스킬 자체의 out-of-scope 항목이 많음 — 이미지 소싱 우선순위, em dash 금지, 컬러 채도 절제 원칙만 차용).
- `DESIGN_VARIANCE: 8` / `MOTION_INTENSITY: 5` / `VISUAL_DENSITY: 4` — A4 전환으로 변주를 6 → 8로 올렸다(맵 캔버스 + 탭바 없음은 워크스페이스에서 유일한 골격이다). 모션은 6 → 5로 내렸다: 지도 위에서 요소가 많이 움직이면 위치가 흔들리는 것처럼 읽힌다. 지속 모션은 현재 위치 맥동 하나뿐이다.
- 관리자 분리: 관리자 콘솔은 별도 프로젝트 `community/waypoint-admin`(URL `/community/waypoint-admin`)이며 **셸 아키타입 C3(상단 커맨드 바)** 을 쓴다 — 워크스페이스에서 유일하게 사이드바가 없는 콘솔이다. 이 콘솔의 하루는 신고 처리와 게시글 검수로 끝나 네비게이션보다 처리(triage)가 압도적이라, 상시 236px 다크 레일이 낭비된 픽셀이기 때문이다. 사이드바/264px 드로어/헤더 시계가 전부 없어졌고, 본문은 `max-w-[1120px]` 좁은 단일 컬럼이며, 헤더 우측에는 시각 대신 **처리 대기 건수**가 있다. 모바일에서는 상단 내비가 가로스크롤 세그먼트로 접힌다. 화면 코드는 이 프로젝트의 `components/admin/`에 있고, 토큰(`styles/waypoint.css`)을 그대로 상속한다. `waypoint-admin`에는 별도 `styles/`·`design.md`를 두지 않는다. 사용자 앱 쪽에는 관리자 진입점을 두지 않는다.
- 목업 내 표시 기간: 2025.10 ~ 2026.02 (가입일, 거래 일자, 채팅 타임스탬프, 공지/운영 로그 전부 이 구간 내 날짜만 사용).

## Tokens / 팔레트

**팔레트 구성 3 — 듀오톤** (CLAUDE.md `## Color`). 44개 중 41개가 "라이트 뉴트럴 + 액센트 1개"라 색이 달라도 인상이 같아진다. 이 제품의 정체성은 "집과 직장, 두 지점 사이의 동선"이라 액센트 하나로는 출발과 도착을 구분할 수 없다. 대등한 두 색을 둔다: `--wp-accent` `#3454D1`(집 / 내 동네)와 `--wp-accent-2` `#0F8F8A`(직장 / 동선 반대편). 지도 핀, 동선 폴리라인의 그라디언트 스트로크, 시트 세그먼트가 전부 이 두 색의 관계로 읽힌다 — 장식이 아니라 의미다. 지도 표면 토큰(`--wp-map-land/block/road/water/park`)도 함께 추가했다.

컴포넌트 스코프 CSS 변수, `.waypoint` 클래스 아래 정의 (`styles/waypoint.css`). "AI 퍼플" 및 베이지+브라스 프리미엄 컨슈머 클리셰를 피하고, 냉정한 뉴트럴 위에 코발트(집)와 틸(직장) 두 축으로 구성한다 — 둘 다 웨이파인딩/교통 노선을 연상시키는 계열이라 함께 놓아도 브랜드가 흐트러지지 않는다.

두 액센트는 **의미로 갈린다**: `--wp-accent`(코발트)는 집 / 내 동네 / 주요 CTA, `--wp-accent-2`(틸)는 직장 / 웨이스팟 / "내 동선"이다. 색을 늘린 것이 아니라 축을 나눈 것이므로, 어느 쪽도 장식으로 쓰지 않는다 — 새 요소를 추가할 때 "이건 출발 쪽인가 도착 쪽인가"로 색을 고른다. 동선 폴리라인은 두 색을 잇는 `linearGradient` 하나로 그려 이 관계 자체를 보여준다.

관리자 콘솔은 이 토큰을 그대로 상속한다. 셸이 C3(상단 커맨드 바)라 잉크 반전 사이드 레일이 없어졌고, 사용자 앱과의 구분은 레일 색이 아니라 **레이아웃 자체**(사이드바 없음, 좁은 1120px 단일 컬럼, 처리 대기 배지)가 담당한다.

예외적으로 채팅 상세의 웨이스팟 공유 Floating 버튼은 `--wp-success`를 쓴다 — 채팅 버블(내 메시지)이 이미 `--wp-accent`라 같은 색이면 버튼이 버블에 묻혀 버리고, "안전한 장소" 의미와도 초록이 더 맞는다. 웨이스팟 즐겨찾기 별 아이콘(채워짐)은 `--wp-warn`(별=골드 관용색)을 쓴다. 둘 다 이미 정의된 시맨틱 토큰 재사용이라 새 색을 늘리지 않는다.

## Shape

- 히어로급 카드(신뢰지수 카드, 내 동선 홈 배너, 온보딩 진행 카드): Double-Bezel — 아우터 셸 `rounded-[28px]` + 이너 코어 `rounded-[22px]`, 셸은 `p-1.5` 패딩과 `bg-[var(--wp-surface-soft)]`.
- 일반 카드: `rounded-[18px]`, `border border-[var(--wp-border)]`.
- 칩/배지: `rounded-full`.
- 프라이머리 버튼: `rounded-full`(필 버튼), 트레일링 아이콘은 버튼-인-버튼(`h-8 w-8 rounded-full` 별도 원 안에 중첩).
- 인풋: `rounded-[14px]`.
- 웨이스팟 지도 핀 마커: `rounded-full` 캡슐 + 하단 포인터(순수 CSS).

## 기기 프레임 안쪽 규칙

- `PhoneFrame`은 기본값(흰 배경, glow 없음) 그대로 사용, 단일 iPhone 16 Pro 프레임.
- A4에는 하단 탭바가 없다. 엣지에 고정되는 것은 **바텀시트**(`components/bottom-sheet.tsx`),
  지도 위 플로팅 칩/검색바, 채팅 상세의 웨이스팟 공유 Floating 버튼이고 전부 불투명
  서페이스(`bg-[var(--wp-surface)]`, `bg-white`)만 쓴다. `backdrop-blur`/`backdrop-filter`는
  이 프로젝트 어디에도 쓰지 않는다.
- 시트는 상단만 `rounded-t-[20px]`한다. 하단은 `PhoneFrame`의 클립이 처리하므로 여기서
  다시 둥글리면 코너가 이중으로 파인다.
- 엣지 고정 UI는 항상 화면 박스 안쪽 `absolute`(음수 오프셋 금지, `fixed` 금지).
- 매 화면 완성 후 프레임 하단 모서리에 흰 틈이 새지 않는지 확인.

## Motion

**앞선 프로젝트와 다르게 한 것** (CLAUDE.md `## Motion` → "스케일 복제 금지"):

이전 값은 `.wp-enter` `420ms cubic-bezier(0.16, 1, 0.3, 1)` + `translateY(8px)`에
스프링 `stiffness 300 / damping 30`이었다. 각각 워크스페이스 CSS 11개, 파일 12개가
쓰는 값 그대로다. A4는 지도가 홈이라 "화면이 떠오르는" 모션 자체가 맞지 않는다 —
지도는 팬되고, 시트는 스냅되고, 핀은 떨어진다. 셋을 분리했다.

| 모션 | 값 | 이유 |
| --- | --- | --- |
| 진입 `.wp-enter` | `240ms cubic-bezier(0.33, 1, 0.68, 1)`, opacity + `scale(1.012)` | 지도는 이동하지 않는다. `translateY` 제거 |
| 시트 스냅 `.wp-sheet` | `340ms cubic-bezier(0.32, 0.72, 0, 1)` transform | 진입과 다른 곡선이라 "시트를 끌어올린 것"으로 읽힌다 |
| 핀 낙하 `.wp-pin-drop` | `300ms cubic-bezier(0.34, 1.4, 0.64, 1)`, `index * 45ms` stagger | 유일하게 오버슈트가 있는 곡선 — 핀이 지도에 얹히는 물성 |
| 동선 드로잉 `.wp-route-draw` | `1400ms`, `stroke-dashoffset` | 집 → 직장이 그려지는 한 줄이 제품 개념 자체를 보여준다 |
| 현재 위치 `.wp-here` | `2.4s` 무한 맥동 | 화면당 하나뿐인 무한 루프. 실제 상태(내 위치)를 뜻한다 |

- 버튼 프레스: `active:opacity-60`. `scale`을 쓰지 않는다 — 지도 위 핀이 축소되면 위치가
  움직인 것처럼 읽힌다.
- 온보딩 단계 전환: 진행 바는 `width` transition.
- 전부 `prefers-reduced-motion: reduce`에서 정지한다(`styles/waypoint.css`).
