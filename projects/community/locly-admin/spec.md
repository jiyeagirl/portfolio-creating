# LOCLY 운영자 콘솔 — Product Spec

## 1. Overview

LOCLY 운영자 콘솔은 나인구청·나인동 주민센터 담당자만 사용하는 **별도 관리자 서비스**다.
주민이 쓰는 [LOCLY](../locly/spec.md)와 화면·URL·로그인 주체를 완전히 분리한다.

- **URL**: `/community/locly-admin` (주민용 서비스는 `/community/locly`)
- **사용자**: 지자체 운영 담당자 (예: 나인구청 소통협력관 김나인)
- **분리 이유**: 주민용 화면에 관리자 진입점이 있으면 일반 주민 계정이 운영 권한을 가진
  것처럼 읽힌다. 실제 서비스와 마찬가지로 관리자는 별도 주소와 별도 계정으로 접근한다.

## 2. 공유 자원

같은 제품군이므로 아래는 `projects/community/locly/`에서 그대로 가져다 쓴다. 데이터
정의를 두 벌로 복제하지 않기 위한 의도적인 의존이다.

- `lib/mock-data.ts`, `lib/types.ts` — 회원·게시글·신고·행사·가게·주민제안 데이터
- `components/site/ui.tsx` — 브랜드 마크, 아바타, 별점 등 공통 프리미티브
- `styles/locly.css` — 색상·타이포 토큰 (`.locly` 스코프)

관리자 전용 컴포넌트(`components/admin-*.tsx`)는 이 폴더 안에만 둔다.

## 3. Information Architecture

좌측 다크 사이드바로 전환되는 6개 영역. 세 그룹(대시보드 / 운영 / 콘텐츠)으로 묶는다.

1. **운영 현황** — 전체 회원, 누적 게시글, 오늘 방문, 미처리 신고 지표 타일 /
   주간 방문자 추이 / 인기 게시판 / 처리 대기 큐 / 최근 등록 게시글
2. **회원 관리** — 닉네임·이메일 검색, 상태·권한 필터, 페이지네이션, 상세 드로어,
   이용 제한 및 해제, 운영 기록
3. **게시글 · 신고** — 신고 접수 목록과 처리 드로어(숨김 / 반려 + 처리 메모),
   게시판별 게시글 관리와 숨김·복구
4. **행사 관리** — 주민 신청 행사 승인/반려, 공식 행사 등록 드로어, 공식 행사
   신청 현황·후기 수
5. **동네 가게** — 가게 등록 승인/반려, 등록 가게 목록과 이벤트 등록 드로어,
   주민 후기 관리(숨김)
6. **주민참여** — 정책 제안 마스터-디테일(처리 단계 진행, 담당 부서 답변 작성),
   설문 결과 확인과 설문 생성 드로어

## 4. Non-goals

- 실제 인가·감사 로그, 권한 그룹 관리
- 주민용 화면으로 이동하는 링크 (두 서비스는 서로 진입점을 두지 않는다)
- 실제 알림 발송, 데이터 내보내기

## 5. 스타일

`스타일:` 지정 없음. 디자인 소스는 주민용 LOCLY와 같은
`design-systems/claude_design_compact.md` 토큰이며, 밀도만 운영 도구 수준으로 올린다.

- 타이포그래피는 **Pretendard 단일 서체**(워크스페이스 `CLAUDE.md` 고정 규칙).
- 사이드바에만 다크 표면(`--lc-dark`)을 쓰고, 본문은 크림 캔버스를 유지한다.
- 상태 표시에 코랄을 쓰지 않는다. 승인은 teal, 대기는 amber, 반려·제한은 error.
  코랄은 주요 액션 버튼에만 남긴다.
- 차트는 외부 차트 의존성 없이 SVG로 직접 그린다.
