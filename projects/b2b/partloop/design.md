# PartLoop Design

테스트용 3화면 콘솔. 구매 담당자가 하루 종일 발주 목록과 상세를 오가며 처리하는 도구라서 셸은 상단 바로 줄이고, 본문 폭을 표에 쓴다. `spec.md`가 `디자인시스템: apple_compact`를 지정해서 색, 반경, 컴포넌트 문법은 `design-systems/apple_compact.md`를 따른다.

## 아키타입

- **고른 것: C3 상단 커맨드 바 (사이드바 없음).** 화면이 3개이고 하루가 목록, 작성, 상세 사이를 오가는 처리(triage) 업무다. 상시 레일은 낭비된 픽셀이다.
- **배제한 후보 1, C1 다크 레일.** 내부 슈퍼관리자용이고 IA 5개 이상일 때 쓰는 셸이다. 여기는 화면 3개의 구매사 담당자라 맞지 않고, 이미 b2b에 4개가 점유했다.
- **배제한 후보 2, C4 아이콘 레일 + 섹션 리스트.** IA가 2단계일 때 쓰는 셸이다. 뷰가 3개뿐이라 레일과 섹션 컬럼이 비게 되고, logisync가 b2b에서 점유했다.
- **같은 b2b 안 중복 없음:** assetflow, buildbid, genderinsight, orderlog는 C1, logisync는 C4. C3는 b2b에서 처음이다.
- **이 아키타입에서 쓰지 않는 부품:** 사이드바 레일, 모바일 드로어와 스크림, 헤더 우측 시계, 사이드 푸터 블록(펜딩 칩 등), 내비 항목 앞 장식 점, 하단 탭바, 카드 4개짜리 KPI 줄.

## 적용 규칙

해석: 부품 수발주 콘솔 for 매일 발주를 올리고 납품을 확인하는 제조사 구매 담당자. 다이얼 V3 / M2 / D6.

- `DESIGN_VARIANCE` 3: 콘솔 표 화면이라 정형 그리드. 세 화면의 골격만 다르게 한다(머리 타일 + 요약 한 줄 + 표 / 머리 타일 + 폼 + 우측 요약 카드 / 머리 타일 + 진행 단계 + 문서형 상세).
- `MOTION_INTENSITY` 2: 화면 진입 한 번과 눌림 피드백만 움직인다.
- `VISUAL_DENSITY` 6: 이전 판은 7이었다. apple_compact의 44px 터치 타깃(버튼, 입력)이 행 높이를 키워서 한 단계 낮췄다. 카드 상자 대신 1px 선과 타일 색 전환으로 구분하고 숫자는 `tabular-nums`.
- 읽은 문서: `mockup-craft` SKILL.md, `references/anti-slop.md`, `references/console.md`, `design-systems/apple_compact.md`. 외부 skill은 적용하지 않았다.
- 우선순위: CLAUDE.md UI Generation Rules(Pretendard, 8px 그리드, 금지 문자) > apple_compact > `mockup-craft`. apple_compact의 SF Pro는 Pretendard로 대체했다.
- 같은 모양 KPI 카드 4개 대신, 세로 헤어라인으로 나눈 한 줄 지표를 쓴다.

## Tokens, 팔레트

팔레트 구성 1(단일 액센트, 라이트 뉴트럴). 이유: 디자인시스템 지정. 액센트는 apple_compact의 `primary` 하나뿐이고 다른 브랜드 색은 추가하지 않는다. 상태 배지 색은 브랜드 색이 아니라 기능색이다.

| 토큰 | 값 | 출처 | 용도 |
| --- | --- | --- | --- |
| `--pl-paper` | `#FFFFFF` | canvas | 본문 타일, 입력 바탕 |
| `--pl-parchment` | `#F5F5F7` | canvas-parchment | 페이지 머리 타일, 행 hover |
| `--pl-ink` | `#1D1D1F` | ink | 본문 |
| `--pl-mute` | `#6E6E73` | ink-muted-48 조정 | 보조 텍스트 |
| `--pl-hairline` | `#E0E0E0` | hairline | 표 구분선, 카드 테두리 |
| `--pl-hairline-strong` | `#D2D2D7` | surface-chip-translucent | 칩 테두리, 지표 구분선 |
| `--pl-primary` | `#0066CC` | primary | 주 버튼, 링크 |
| `--pl-primary-focus` | `#0071E3` | primary-focus | 포커스 링, 선택 칩 테두리, hover |
| `--pl-nav` | `#000000` | surface-black | 상단 바 |
| `--pl-on-nav-muted` | `#CCCCCC` | body-muted | 상단 바 비활성 링크 |
| `--pl-tile` | `#272729` | surface-tile-1 | 상단 바 아바타 |

원본 `ink-muted-48`(`#7A7A7A`)은 흰 바탕 대비가 4.3:1이라 CLAUDE.md의 WCAG AA 규칙에 걸려 `#6E6E73`(5.1:1)으로 한 단계 진하게 썼다. 이 한 곳만 원본과 다르다.

상태색은 파스텔 배경에 짙은 글자, 의미는 모든 화면에서 같다.

| 상태 | 톤 | 배경 | 글자 |
| --- | --- | --- | --- |
| 승인 대기 | 대기 | `#FCF0D0` | `#7A5200` |
| 수락 대기 | 중립 | `#ECECF0` | `#48484A` |
| 진행 중 | 진행 | `#E3EEFA` | `#0A4F99` |
| 지연 | 조치 필요 | `#FDE6E3` | `#A3281D` |
| 납품 완료 | 완료 | `#E1F3E5` | `#1D6B35` |

5단계 톤 구조(대기, 진행, 조치 필요, 완료, 중단) 중 이 프로젝트에는 취소가 없어서 중단 자리에 수락 대기(중립)를 쓴다. 회색 계열은 전부 쿨 하나다.

## Shape

apple_compact의 radius 문법을 따른다. 섞지 않는다.

- pill(9999px): 액션. 버튼, 입력, 선택 박스, 탭 칩, 상태 배지.
- lg 18px: 카드. 발주 요약 카드, 알림 줄, 여러 줄 입력(메모).
- 원형 44px: 유틸리티 아이콘 버튼(페이지 이전/다음, 품목 삭제).
- none 0px: full-bleed 타일(페이지 머리). 색 전환(흰색, 파치먼트)이 섹션 구분선이다.
- 그림자는 쓰지 않는다(원본이 제품 이미지에만 허용). 그라데이션도 쓰지 않는다.
- 구분선은 행 아래 한 줄만. 표에 zebra와 위아래 테두리를 같이 쓰지 않는다.
- 아이콘은 Phosphor 한 패밀리, 기본 regular, 활성 내비만 fill.

## Typography

- Pretendard 하나. 발주번호도 모노 없이 Pretendard + `tabular-nums`.
- apple_compact 타입 스케일에서 골랐다(CLAUDE.md의 "본문 크기는 디자인시스템을 따른다"). 이전 판의 13.5/20과 다르다.
  - 페이지 제목: display-md 34px / 40px / 600 (원본의 줄 높이 1.47은 한 줄 제목에 과해서 40px로 줄임)
  - 섹션 제목: tagline 21px / 25px / 600
  - 본문, 표, 버튼: caption과 button-utility 14px / 20px / 400, 자간 -0.016em(원본 -0.224px의 비율)
  - 라벨과 보조: fine-print 12px
  - 지표 숫자: 34px / 40px / 600, 합계 숫자 28px / 36px / 600
- 굵기는 400과 600만 쓴다(원본의 300 / 400 / 600 / 700 사다리 안). **500은 쓰지 않는다.**
- 큰 숫자 옆에 단위를 붙이지 않는다. 단위는 라벨(`이번 달 발주 금액 (만원)`)이나 표 헤더(`금액 (원)`)로 옮긴다.
- 전역 `word-break: keep-all; overflow-wrap: break-word`. 존댓말은 합니다체, 라벨과 버튼은 명사형.

## 사진 매핑

사진 없음. 화면은 표, 폼, 진행 단계 중심이고 부품 품목은 텍스트로 충분하다. 사진 슬롯이 없으므로 사진 요청 목록도 없다.

## 셸 레이아웃

- 상단 바는 apple_compact `global-nav`: 검정 배경, 높이 44px, 12px 링크, `sticky top-0`. 반투명과 `backdrop-blur`는 쓰지 않는다. 이전 판의 56px 종이색 바에서 바뀌었다.
- 좌측: 브랜드(아이콘 + PartLoop), 수평 내비 2개(발주 현황, 발주 작성). 활성 항목은 흰색 글자와 아이콘 fill, 비활성은 `#CCCCCC`.
- 우측: 계정(이니셜 아바타 + `마정훈 | A테크 구매팀`)만 둔다. 주 액션 버튼은 상단 바에 두지 않는다. 내비의 발주 작성과 같은 의도라 이름이 둘이 되기 때문이고, 목록 화면 머리의 "발주 작성" 버튼이 그 역할을 한다. 모바일(768px 미만)에서는 계정을 숨긴다.
- 본문: 모든 화면이 `PageBand`(파치먼트 full-bleed 타일, 제목과 요약) 다음에 `PageBody`(흰색 타일)가 오는 같은 구조다. 내부 폭은 `mx-auto max-w-[1152px]`, 좌우 패딩 모바일 16px, 데스크톱 32px.
- 페이지 머리는 `min-h-[72px]`로 고정해 화면을 오가도 제목 위치가 같다.
- `lg:`(1024px) 분기: 작성 화면의 2컬럼이 `lg:` 이상에서만 나란히, 미만에서는 1컬럼.
- 모바일: 드로어 없음. 내비가 라벨 짧은 2개라 한 줄에 들어간다.
- 사용자 콘솔만 있고 관리자 콘솔은 없다.

## 표 밀도, 컬럼 예산

- 발주 목록은 5열: 발주번호, 공급사(품목 요약을 둘째 줄), 금액(원), 납기일, 상태. 열 상한 6열 안.
- 컬럼 폭: 발주번호 148, 공급사 가변(최소 240), 금액 128, 납기일 128, 상태 112. 합계 최소 756px이고 표 `minWidth`를 760으로 둔다. 1440px 뷰포트에서 본문 폭 1152 안에 여유 있게 들어가고, 모바일은 `overflow-x-auto` 안에서 가로로 민다. 납기일 열은 앞 금액 열과 붙어 읽히지 않게 좌측 패딩 32px을 준다.
- 셀 세로 패딩 14px, 행 높이 약 56px(공급사 열 두 줄 기준). 숫자 열은 오른쪽 정렬과 `tabular-nums`.
- 한 페이지 8행, 하단 페이지네이션(이전/다음 원형 버튼과 "1 / 2"). 탭 칩의 건수와 표 결과는 같은 필터에서 계산된다.
- 탭은 `configurator-option-chip` 문법: pill 칩, 선택되면 2px `primary-focus` 테두리와 600 굵기.
- 품목 표(작성, 상세)는 4~5열: 품목(규격을 둘째 줄), 수량, 단가(원), 금액(원). 가장 긴 품목명은 `min-w-0 truncate`에 `title`을 준다.
- 좌우 높이가 다른 2컬럼 그리드에는 `items-start`를 준다.
- 빈 상태: 필터 결과가 0건이면 표 자리에 "조건에 맞는 발주가 없습니다."와 "필터 초기화" 버튼 한 줄.

## Motion

- 화면 진입: 200ms, `cubic-bezier(0.25, 0.1, 0.25, 1)` (CSS `ease`), 불투명도만 0에서 1. 이동은 쓰지 않는다. 앞선 프로젝트의 420ms expo-out과 다르게 골랐다. 이유: 화면이 바뀌었음을 알리는 상태 전환.
- 눌림 피드백: `translateY(1px)` 하나로 고정. apple_compact는 버튼 active를 `scale(0.95)`로 적었지만, CLAUDE.md `## Motion`이 눌림 피드백은 디자인시스템이 있어도 새로 고르게 하고 `scale` 계열은 앞선 프로젝트에 번져 있어 이쪽을 택했다. hover는 배경 톤.
- 표 행, 지표, 진행 단계를 하나씩 등장시키지 않는다. 카운트업 없음.
- `prefers-reduced-motion: reduce`에서 진입과 눌림 이동을 끈다.
