# CIVICPIN - Product Spec

## 1. Overview

CIVICPIN은 지자체가 설치한 QR 코드를 스캔하는 순간부터 주변 생활안전, 편의시설과
골목형 상점가 정보를 한 번에 확인하고, 도보 길찾기까지 하나의 흐름으로 연결하는
모바일 웹 서비스이다.

QR 스캔 위치를 기준으로 지도, 시설, 상점, 축제 정보를 유기적으로 이어 보여주며,
운영자는 별도의 관리자 페이지에서 시설, 상점, 축제 데이터를 등록, 수정하고
사용자 오류 신고를 검수하여 공공데이터 기반 서비스의 정합성을 지속적으로
관리할 수 있다.

- **플랫폼**: Mobile Web (iPhone 기준, 393×852pt 반응형)
- **포지셔닝**: 지자체 생활안전시설 안내 + 골목상권 활성화를 결합한 공공 QR 서비스
- **제작 목적**: 포트폴리오용 고품질 UI/UX 목업. 실제 지자체명, 지역명, 상점명, 
 좌표 등 식별 정보는 전부 가명 처리하며, 실제 API 연동, DB, 인증 로직은
 구현하지 않고 화면 구조와 인터랙션 디테일을 우선한다.

## 2. Non-goals

- 실제 GPS/위치 API, 지도 API(카카오맵 등) 연동 - 정적 목업 지도 이미지/컴포넌트로 대체
- 실제 공공데이터 API 연동 및 실시간 데이터 동기화
- 로그인, 인증, 결제, 실제 오류 신고 접수/알림 파이프라인 등 비즈니스 로직
- 실제 지자체명, 행정동명, 상점가명, 매장 상호, 좌표 등 식별 가능한 실데이터 사용
 → 전 화면 가명, 가상 데이터로 대체 (아래 8. Anonymization Guidelines 참조)

## 3. Information Architecture

```
/civicpin → /civicpin/home 로 리다이렉트
/civicpin/home → 1. QR 진입 / 통합 메인
/civicpin/map → 2. 주변 정보 지도
/civicpin/directions → 3. 길찾기
/civicpin/districts → 4. 골목형 상점가 목록/지도
/civicpin/districts/[districtId] → 5. 상점가 상세
/civicpin/districts/[districtId]/stores/[storeId] → 6. 개별 매장 상세
/civicpin/festivals → 7. 상점가 축제 목록/상세
/civicpin/admin → 8. 관리자 대시보드
/civicpin/admin/data → 9. 시설, 상점 데이터 관리
/civicpin/admin/reports → 10. 오류 신고, 콘텐츠 관리
```

> **구현 시 반영한 차이**: 위 경로 목록은 IA를 설명하는 용도로 두고, 실제 라우팅은
> 워크스페이스 규칙(`CLAUDE.md`의 "One URL per project")을 따랐다. 사용자 화면 1~7은
> `/youngin/real` **한 URL** 안에서 내부 상태로 전환하고(화면은 `href` 대신 `onNavigate`
> 콜백을 받는다), 관리자 화면 8~10은 `/youngin/real-admin` 한 URL 안에서 전환한다.
> 6절의 `app/civicpin/**`, `public/civicpin/` 경로도 같은 이유로 각각
> `projects/youngin/real/`, ES 모듈 import로 대체했다.

QR 진입(메인)을 허브로, 사용자 화면(2~7)과 관리자 화면(8~10)이 뻗어나가는 구조:

- 메인 상단/배너 → 상점가, 축제 바로가기
- 메인 하단 내비게이션 or 지도 내 필터 → 주변 정보 지도
- 지도 내 시설/매장 선택 → 길찾기
- 상점가 카드 탭 → 상점가 상세 → 입점 매장 탭 → 매장 상세
- 상점가 상세 내 축제 배너 → 축제 목록/상세
- 관리자 화면은 별도 진입점(관리자 로그인 목업)에서 대시보드 → 데이터 관리 /
 오류 관리로 분기
- 각 서브 화면은 좌상단 Back으로 이전 화면 복귀

## 4. Screens & Requirements

### 4.1 QR 진입 / 통합 메인

- QR 스캔 위치 안내 배지 (예: "OO시 △△동, 12번 QR" 형태의 가상 코드 표기)
- 생활안전시설 / 골목형 상점가 / 축제 바로가기 카드 3종
- 현재 위치 주변 추천 정보 캐러셀 (가상 시설, 매장 카드)
- 주요 배너 / 공지 영역
- 상단 상태바(시간/신호/배터리) 및 지자체 상징 요소는 실제 로고 대신 추상화된
 플레이스홀더 엠블럼 사용

### 4.2 주변 정보 지도

- QR 위치를 중심점으로 한 지도 (도로망, 건물 블록만 표현된 추상화 지도, 실제
 행정구역 라벨 없음 - 8절 참조)
- AED, 화장실, 쉼터, 대피소, 상점가, 매장 마커 표시
- 카테고리 필터 칩 (전체 / 안전시설 / 편의시설 / 상점가)
- 마커 탭 → 하단 시트로 시설/매장 요약 카드 노출 → 상세 진입

### 4.3 길찾기 화면

- QR 위치를 출발점으로 자동 고정, 목적지는 지도/검색으로 선택
- 도보 경로 라인 표시 (추상화 지도 위 폴리라인)
- 예상 거리 / 소요시간 상단 요약 카드
- 구간별 방향 안내 리스트 (좌회전/직진 등 아이콘 + 텍스트, 가상 도로명 사용)

### 4.4 골목형 상점가 목록/지도

- 다수 상점가를 리스트/지도 토글로 탐색 (가명 예: "A 상점가", "B 상점가")
- 현재 위치 기준 거리순 정렬
- 상점가 구역 경계를 지도 위 폴리곤으로 표시 (실제 지명 없이 구역 코드만 노출)
- 카드별 주요 업종 태그, 대표 이미지(가상 스톡 이미지)

### 4.5 상점가 상세

- 상점가 소개 카피 (가명 처리된 스토리텔링, 실존 지명 언급 없음)
- 구역 정보 / 주요 업종 비중 그래프
- 입점 매장 리스트 (가명: "A 정육점", "B 카페", "C 세탁소" 등 유형+가명 조합)
- 인근 AED, 화장실, 주차장 등 연계 시설 카드 (안전시설 ↔ 상권 정보 연계 강조)
- 추천 코스 (예: "시장 입구 → 중앙로 → 공영주차장" 형태의 가상 동선)

### 4.6 개별 매장 상세

- 업체 유형 + 가명 상호 (예: "A 시장 청과상회")
- 주소는 가상 도로명 주소로 표기 (행정동만 가명 `△△동`, 도로명과 건물번호는 실주소 형식).
  "상점가 내 3구역" 상대 위치는 주소 아래 보조 줄로만 쓴다 — 상대 위치만으로는 처음 온
  사람이 위치를 가늠할 수 없다
- 온누리상품권 가맹 여부 배지
- 길찾기 진입 버튼, 소속 상점가 정보 링크

### 4.7 골목형 상점가 축제 목록/상세

- 인근 축제 리스트 (가명 예: "OO 골목상권 가을 축제")
- 기간, 시간, 프로그램, 장소(가상 좌표), 부스/편의시설 정보
- 축제 홍보 콘텐츠 이미지 (가상 이미지)

### 4.8 관리자 대시보드

- 시설, 상점, 축제 등록 현황 요약 카드 (숫자는 가상 통계)
- 최근 수정 내역 타임라인
- 오류 신고 현황 위젯 (신규/처리중/완료 상태별 카운트)
- 전체 데이터 관리 현황 개요 차트

### 4.9 시설, 상점 데이터 관리

- 시설/매장 검색 및 필터
- 등록, 수정, 삭제 폼 (모두 mock, 실제 저장 없음)
- 위치/주소 관리 필드 (가상 좌표계 사용)
- 온누리상품권 가맹 여부 토글
- 데이터 기준일 표기, 공공데이터 기반 정보 보정 이력 로그

### 4.10 오류 신고, 콘텐츠 관리

- 사용자 오류 신고 리스트 (가명 신고 내용)
- 오류 검수/처리 상태 워크플로우 (접수 → 검토 → 반영 → 완료)
- 시설 정보 수정 화면 연계
- 축제, 배너, 추천 콘텐츠 관리 탭
- 수정 이력 로그

## 5. Data Model (mock)

```ts
Facility {
 id, type("AED"|"화장실"|"쉼터"|"대피소"),
 displayName, // 가명: "OO시 △△동 쉼터 1호" 형태
 address, // 가상 도로명 주소 "△△동 시장로 9"
 relativeLocation, // 주소를 보조하는 건물 안/골목 안 위치 텍스트
 coordinates // 가상 좌표 (실제 지역과 무관한 값)
}

District {
 id, name, // 가명: "A 상점가"
 zoneCode,
 mainCategories[],
 storeIds[],
 festivalIds[]
}

Store {
 id, districtId,
 name, // 가명: 유형 + 알파벳 조합
 category,
 onnuriAccepted: boolean,
 relativeLocation
}

Festival {
 id, districtId,
 name, // 가명: "OO 골목상권 가을 축제"
 period, programs[], venue, boothInfo[]
}

Report {
 id, targetType("Facility"|"Store"|"Festival"),
 targetId, status("접수"|"검토"|"반영"|"완료"),
 reportedAt, note
}
```

## 5.5. 관리자는 별도 프로젝트

관리자 화면(8~10)은 사용자 앱과 **다른 URL**에 둔다. 실제 서비스처럼 주소도 계정도 다르고,
사용자 화면에는 관리자 진입점(내비 항목, 로그인 역할 선택지)을 두지 않는다.

- 사용자 앱: `projects/youngin/real` → `/youngin/real`
- 운영 콘솔: `projects/youngin/real-admin` → `/youngin/real-admin`

`-admin`은 URL을 하나 더 얻기 위한 얇은 엔트리(`src/index.tsx` + `src/meta.ts`)일 뿐이고,
관리자 화면 코드는 전부 본 프로젝트의 `components/admin/` 안에 있다(이 워크스페이스의
`assetflow-admin`, `orderlog-admin`과 같은 구성). `-admin`은 자체 `styles/`나 `design.md`를
갖지 않고 본 프로젝트의 토큰을 그대로 상속한다.

## 6. Tech Constraints

- 기존 워크스페이스(Next.js App Router, Tailwind, shadcn 패턴, Phosphor Icons,
 Motion, Pretendard)를 그대로 재사용한다.
- 신규 npm 패키지 설치 없음.
- 신규 Next.js 프로젝트 생성 없음 - 기존 저장소의 `app/civicpin/**` 라우트로 편입.
- 프로젝트 전용 코드는 `projects/publicservice/civicpin/{components,lib}`에 위치.
- 정적 이미지 자산은 `public/civicpin/`에 위치.
- 지도는 실제 지도 타일/API 대신 정적 SVG 또는 목업 이미지(도로, 건물 블록만
 표현, 라벨 없음)로 구현한다.

## 7. Screen Priority (강조 화면)

포트폴리오 임팩트를 위해 아래 5개 화면은 완성도를 높여 우선 작업한다:

1. 3. 길찾기 - QR 출발점 기반 경로 안내 UX
2. 5. 상점가 상세 - 안전시설 ↔ 상권 정보 연계 경험
3. 8. 관리자 대시보드 - 데이터 운영 구조 시각화
4. 9. 시설, 상점 데이터 관리 - 공공데이터 보정 워크플로우
5. 10. 오류 신고, 콘텐츠 관리 - 신고→검수→반영 흐름

노출 순서: 01 메인 → 02 지도 → 03 길찾기 → 04 상점가 목록 → 05 상점가 상세 →
06 매장 상세 → 07 축제 → 08 대시보드 → 09 데이터 관리 → 10 오류 관리
(사용자 경험 → 상권 콘텐츠 → 관리자 운영 순으로 배치)

## 8. Anonymization Guidelines (가명 처리 원칙)

실제 화면 캡처/스크린샷을 포트폴리오에 첨부할 때 다음 규칙을 일괄 적용한다.

| 항목 | 원본 | 가명 처리 |
|---|---|---|
| 지자체명 | 실제 시/군명 | "OO시" |
| 행정동/지역명 | 실제 동/지역명 | "△△동", "1구역" 등 코드형 표기 |
| 상점가명 | 실제 상권명 | "A 상점가", "B 상점가" |
| 매장 상호 | 실제 업체명 | "A 시장 입구 청과상회" 등 유형+위치 조합 가명 |
| 축제명 | 실제 축제명 | "OO 골목상권 가을 축제" |
| 지도 | 실제 지도(라벨, 행정구역 포함) | 도로망, 건물 블록만 남긴 추상화 지도, 지명/좌표 라벨 제거 |
| 좌표/주소 | 실제 좌표, 실제 지번/도로명 | 가상 좌표, 행정동을 가린 가상 도로명 주소(`△△동 시장로 9`) + 보조 상대 위치 |
| 로고/엠블럼 | 실제 지자체 로고 | 추상화된 플레이스홀더 엠블럼 |
| 통계 수치 | 실제 운영 데이터 | 임의 생성한 유사 범위의 가상 수치 |

원칙: 실제 서비스와 구조, 플로우, 인터랙션은 동일하게 유지하되, 식별 가능한
고유명사, 좌표, 수치는 전부 가상 값으로 치환한다.
