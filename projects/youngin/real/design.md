# CIVICPIN — Design Doc

지자체가 설치한 QR을 스캔한 지점을 기준으로 생활안전시설, 골목형 상점가, 축제를 잇고 도보
길찾기까지 연결하는 모바일 웹 서비스. `app` 프리셋(`projects/camera/filmate`) 구조를 참조했다.

운영 콘솔은 별도 프로젝트 **`youngin/real-admin`** (URL `/youngin/real-admin`)으로 분리했다.
화면 코드는 이 프로젝트의 `components/admin/` 안에 있고 `-admin`은 URL을 하나 더 얻기 위한
얇은 엔트리다. 사용자 앱 화면 어디에도 관리자 진입점을 두지 않는다(주소도 계정도 분리).
`-admin`은 `styles/`도 `design.md`도 갖지 않고 이 문서의 토큰을 그대로 상속한다.

## 적용 규칙

- `spec.md`에 `스타일:` / `디자인시스템:` / `프리미엄디테일:` 줄이 **없다.** 따라서 워크스페이스
  `CLAUDE.md`의 UI Generation Rules + `supanova-design-engine`의 판단만 적용했다
  (`design-systems/` 문서는 참조하지 않음).
- `supanova-design-engine`에서 가져온 것: 한국어 카피 품질 기준(번역투 금지, "혁신적인/차세대"
  류 상투어 금지), `word-break: keep-all`, 액센트 1개 제한, 보라/네온 그라데이션 금지,
  섹션마다 레이아웃을 바꿔 동일 카드 그리드를 피하는 원칙. **출력 형식(standalone HTML +
  Tailwind CDN)은 따르지 않는다** — 이 워크스페이스는 `src/index.tsx` React 컴포넌트다.
- 구조(스페이싱 8px 그리드, 타이포 스케일, 라운드, 섀도, 모션 타이밍, 세이프에어리어
  top 59 / bottom 34, 44×44pt 터치 타깃)는 `_reference-design-system.md`(FILMATE)를 그대로
  재사용했다. FILMATE는 다크 테마라 **색은 전면 재정의**했다.
- 다이얼: `DESIGN_VARIANCE` **4** (공공서비스 신뢰감이 우선이라 장식 최소, 대신 섹션 간
  레이아웃 리듬으로 변화를 준다) / `MOTION_INTENSITY` **3** (기능적 전환만) /
  `VISUAL_DENSITY` **6** (시설 목록, 표, 상태 배지가 많은 정보형 서비스).

폴리곤, 경로 폴리라인, 차트 강조 막대에만 쓴다. 홈 화면 상단 헤더가 액센트를 **면으로 쓰는
유일한 자리**이고, 그 외 화면은 중립 캔버스 위에 액센트를 점으로만 찍는다.

**시설 분류색은 지도 마커와 분류 칩에서만** 쓴다. 네 가지로 고정하고 명도/채도를 서로 맞춰
한 벌로 읽히게 했다. 상태색(`ok`/`warn`/`danger`)과 색상값이 겹치는 자리가 있지만(대피소와
warn, AED와 danger) 등장 문맥이 분리되어 있어 의미 충돌이 없다.

## Shape

- 모바일 카드, 사진: `rounded-2xl`(16px)
- 아이콘 타일, 축제 썸네일, 목적지 후보 칩: `rounded-[12px]` ~ `rounded-[14px]`
- 배지, 필터 칩, Primary CTA: `rounded-full` (CTA height 52px)
- 하단 시트: `rounded-t-[24px]`
- **웹 콘솔은 문법이 다르다**: 버튼, 입력, 페이지네이션 `6px` / 카드, 드로어, 배너 `8px` /
  배지 `full`. 같은 이름의 `Badge`, `Button`, `Card`가 모바일과 콘솔에 따로 있는 이유다.
- Shadow: 단일 두꺼운 drop-shadow 금지. `--cp-shadow`(카드), `--cp-shadow-pop`(시트, 겹쳐
  올린 카드) 두 단계 미세 스택만. **웹 콘솔 카드는 그림자 없이 hairline 보더**를 쓴다.

## Typography

Pretendard 고정. FILMATE 레퍼런스의 Apple HIG 스케일을 그대로 재사용한다.

| Role | Size / Line | Weight | 용도 |
|---|---|---|---|
| Display | 27 / 34 | 800 | 홈 헤더 "△△동 시장 입구 버스정류장 기준으로 안내합니다" |
| Title 1 | 20–24 / 27–30 | 800 | 화면 타이틀, 상세 히어로 제목 |
| Title 2 | 17–19 / 23–24 | 700–800 | 섹션 헤더, 카드 제목 |
| Body | 13.5–15 / 20–22 | 400–600 | 본문, 리스트 항목명 |
| Callout | 12–12.5 / 18 | 500–600 | 메타 정보, 캡션 |
| Micro | 10.5–11 / 14 | 600–700 | 배지, 탭 라벨, 구역 코드 |

- 거리(m/km), 도보 분, 건수, 시각, 관리번호, 구역 코드는 `.cp-num` 유틸(`tabular-nums`)로
  자릿수를 고정한다. **별도 모노 패밀리를 두지 않는다** — CLAUDE.md의 "항상 Pretendard"
  규칙과 충돌하지 않게 숫자 폭만 고정하는 방식을 택했다(assetflow의 `af-mono`와 다른 선택).
- 중간점(·)과 em dash(—)는 렌더링되는 텍스트에 쓰지 않는다. 이 프로젝트의 대체 규칙:
  - 이종 메타 필드 나열(거리 / 도보 / 위치, 팀 / 역할) → 파이프 `|` (`components/ui.tsx`의
    `MetaLine`이 이 규칙을 강제한다)
  - 하나의 결합 개념을 가리키는 라벨(`시설 / 상점 데이터`, `오류 신고 / 콘텐츠`,
    `카페 / 디저트`, `부스 / 편의시설`) → 슬래시
  - 문장 안 나열(`AED, 대피소, 쉼터`) → 콤마
  - 페이지네이션의 수 범위(`1–8 / 34`)만 en dash 허용

A 상권 히어로는 342(넓은 차도와 버스가 보이는 시장 거리)에서 195로 교체했다. 이름이
"골목형 상점가"인데 사진은 골목이 아니라 큰길로 읽혀 캡션과 어긋났다. 같은 이유로
`fs-02` 야시장은 274(전광판이 늘어선 도심 번화가)에서 351로 바꿨다. 이 목업의 무대는
동네 골목 상권이라, 사진이 도심 번화가로 보이면 규모 자체가 어긋난다.

**사진을 쓰지 않는 자리와 그 이유**

- **C, D 골목형 상점가**: 내용이 맞는 상권 사진을 찾지 못했다. 아무 사진이나 얹는 대신
  `District.photo`를 optional로 두고, 상세 히어로를 **구역 폴리곤이 그려진 추상 지도**로
  대체한다(`district-detail-screen.tsx`). 이 화면에서는 지도가 사진보다 정보량이 많다.
- **상점가 목록의 B/C/D 행**: 구역 폴리곤을 바운딩 박스에 맞춰 축소한 `ZoneThumb` 타일을
  쓴다. 사진은 "지금 서 있는 상권"인 A 카드 한 장에만 붙여 목록의 위계를 만든다.
- **시설(AED, 화장실, 쉼터, 대피소)과 사진 없는 매장**: Phosphor 아이콘 타일. 이 시설군은
  사진보다 아이콘 인식이 실사용에 맞고, 분류색이 곧 정보다.
- **지도**: 실제 타일/API 대신 정적 SVG(`components/abstract-map.tsx`). spec.md 8절대로
  도로망과 건물 블록만 남기고 지명, 행정구역 라벨, 실좌표를 넣지 않는다.

## 추상화 지도 좌표계

- 모든 좌표(시설, 매장, 구역 폴리곤, 경로 웨이포인트)는 **0~100 정규화 값**이고 실제
  좌표계와 매핑되지 않는다.
- 배경 지오메트리는 `viewBox="0 0 100 100"` + `preserveAspectRatio="none"`으로 컨테이너를
  꽉 채우고, 모든 선에 `vector-effect="non-scaling-stroke"`를 걸어 비등방 스케일에도 선
  굵기가 일정하게 유지된다.
- 마커와 라벨은 SVG가 아니라 **HTML을 `left`/`top` 퍼센트로 얹는다.** 원과 글자가 눌리지
  않으면서 좌표는 배경과 정확히 일치한다.
- `AbstractMap` 루트는 `relative`(마커 좌표 기준)다. 화면을 꽉 채워야 하는 곳에서는 호출부가
  `absolute inset-0` 래퍼를 두고 지도에는 `h-full w-full`을 넘긴다. **같은 엘리먼트에
  `relative`와 `absolute`를 함께 주면 Tailwind 순서상 `relative`가 이겨 높이가 0이 된다.**

### 확대(`view`) — 전체 지도를 그대로 쓰지 않는 곳

0~100 전체를 그대로 보여주면 **가까운 두 지점이 몇 퍼센트 안에 몰려 점처럼 붙어 보인다.**
QR 지점(46, 58)과 공영주차장 AED(64, 70)는 전체 폭의 18%밖에 차이가 나지 않는다.

그래서 `AbstractMap` 에 `view={{ x, y, w, h }}` 창을 넘길 수 있게 했고,
`fitView(points, { aspect, fill, min })` 가 관심 지점들이 화면의 `fill` 비율을 차지하도록
창을 계산한다. SVG 는 `viewBox` 로, HTML 마커는 퍼센트 재계산으로 같은 창을 적용하므로
배경과 마커가 어긋나지 않는다. `aspect` 에는 그 지도 박스의 가로/세로 비를 넘긴다.

| 지도 | fill | 비고 |
|---|---|---|
| 길찾기 히어로 (393×268) | 0.50 | 경로 웨이포인트 기준. `min: 20` 으로 초근거리(15m)에서 과확대 방지 |
| 상점가 상세 히어로, 사진 없는 분기 (393×196) | 0.72 | 구역 폴리곤 기준 |
| 상점가 추천 코스 (353×132) | 0.82 | 폴리곤 + QR 지점 |
| 축제 행사 위치 (353×176) | 0.78 | 폴리곤 + QR 지점 |

지도 탭과 상점가 지도 토글은 **전체 창을 그대로 쓴다.** 네 상권을 한눈에 비교하는 화면이라
확대하면 목적이 깨진다.

작은 지도에서는 라벨을 하나만 남긴다. 축제 행사 위치 지도는 마커 라벨을 빼고 "현재 위치"
라벨만 두는데, 둘 다 두면 좁은 폭에서 서로 겹친다.

## 기기 프레임 안쪽 규칙 (mobile)

`PhoneFrame`의 `overflow-hidden` + `rounded-[50px]` 클립을 뚫지 않도록:

- **`backdrop-blur` 를 화면 어디에도 쓰지 않는다.** 하단 탭바(`bottom-tab-bar.tsx`), 지도
  화면 상단 고정 영역, 길찾기/매장/축제 상세의 하단 고정 CTA 바는 전부 **불투명
  `bg-[var(--cp-surface)]` + hairline 보더**만 쓴다. 반투명 채움(`bg-white/95`)도 금지 —
  스크롤된 내용이 비쳐 렌더링 버그처럼 읽힌다.
- 엣지 고정 UI는 전부 화면 박스 안쪽 `absolute`다. `fixed`와 음수 offset을 쓰지 않는다.
  하단 탭바 `absolute inset-x-0 bottom-0 pb-[34px]`, 하단 CTA 바 `absolute inset-x-0
  bottom-0 pb-[34px] pt-3`.
- 예외: 지도 화면의 지도 레이어만 `-top-[132px]` 음수 offset으로 위로 당긴다. QR 지점이
  하단 시트에 가리지 않고 노출 영역 가운데 오게 하기 위한 것이고, 화면 루트에
  `overflow-hidden`을 걸어 **스크린 박스 안에서만** 잘리도록 했다. 엣지 고정 UI가 아니라
  배경 레이어라 코너 클립과 무관하다.
- 하단 시트는 탭바 위(`bottom-[92px]`)에 얹혀 프레임 모서리에 닿지 않는다.

### 위 규칙을 다 지켜도 모서리가 새던 건 (`PhoneFrame` 마스크)

`backdrop-blur` 도 `fixed` 도 안 썼는데 상점가 상세 / 축제 상세 좌상단, 지도 탭 좌하단에서
**흰 사각형이 검은 섀시 베젤을 덮고** 있었다. 원인은 이쪽 코드가 아니라 Chromium 의 클립
방식이다. `sticky` 앱바(`ScreenHeader`), 스크롤 컨테이너, `absolute` 하단 탭바처럼 **합성
레이어로 승격된 자손**은 조상의 `overflow-hidden` 을 **사각형 경계로만** 적용받고
`rounded-[50px]` 을 무시한다.

`components/shared/phone-frame.tsx` 의 스크린 박스에 `mask-image: linear-gradient(#000,#000)`
(알파가 전부 1인 상수 마스크)를 걸어 클립을 마스크 연산으로 바꿨다. 마스크는 반경을 지키므로
합성 레이어도 둥글게 잘린다. 화면 쪽 코드로는 우회할 수 없는 문제라 공용 컴포넌트에서 막았고,
지우면 sticky 헤더나 엣지 고정 바가 있는 화면부터 바로 재발한다.

### 화면 전환 애니메이션에 `transform` 을 쓰지 않는 이유

`src/index.tsx` 는 화면을 `<div className="h-full cp-screen-in">` 로 감싼다. 이 래퍼에
`transform` 이 걸리면 **absolute 자식의 컨테이닝 블록이 화면(852px 고정)이 아니라 이 래퍼**가
된다. 래퍼는 `h-full` 이라 852px이지만 스크롤 컨테이너 안에서 본문과 함께 밀려 올라가므로,
`absolute inset-x-0 bottom-0` 로 붙인 하단 CTA 바가 화면 바닥에 고정되지 않고 **본문 중간까지
따라 올라와 구간 안내 리스트를 덮는다.** 애니메이션이 끝나 `transform: none` 이 된 뒤에도
Chromium 은 채움(fill) 상태를 유지해 증상이 남는다.

그래서 `.cp-screen-in` 은 **opacity 페이드만** 쓴다. 하단 고정 바를 쓰는 화면
(길찾기 / 매장 상세 / 축제 상세)이 있는 한 이 클래스에 `transform` 을 다시 넣지 않는다.
슬라이드가 필요하면 바를 애니메이션 래퍼 밖(`BottomTabBar` 처럼 스크롤 컨테이너 직속)으로
빼는 것이 먼저다.

### 사진, 지도 위에 겹쳐 올리는 블록은 카드가 아니라 시트

히어로(사진 또는 지도) 아래 블록을 **좌우 여백이 있는 카드**(`-mt-6 px-5` + `rounded-2xl`)로
겹치면, 히어로는 full-bleed인데 카드는 20px 안쪽이라 **카드 양옆으로 히어로 끝단이 20px씩
비어져 나온다.** 사진 아래에 정체불명의 띠가 생겨 "사진과 본문이 깨진" 것처럼 읽힌다.

그래서 길찾기, 상점가 상세, 매장 상세, 축제 상세 네 화면의 첫 블록은 전부
**화면 폭을 꽉 채우고 위쪽만 둥글린 시트**로 쓴다:

```
<section className="relative z-10 -mt-6 rounded-t-[24px] bg-[var(--cp-surface)] px-5 pb-5 pt-5">
```

- `relative z-10`은 필수다. 지도 마커가 `z-10`/`z-20`으로 쌓여 있어 빼면 마커 레이어가
  시트 위로 새어 나온다.
- 히어로 위에 흰 글씨(배지, 제목)를 얹는 화면은 시트가 24px 파고들므로 오버레이 컨테이너에
  `p-5 pb-11`을 준다. 그래야 제목 아래 20px가 남는다.
- 사진 대신 **지도**를 히어로로 쓰는 분기(사진 없는 상권)는 배경이 밝아 흰 글씨가 뜬다.
  그때만 그라데이션을 더 일찍, 더 짙게 건다
  (`rgba(20,24,30,0) 18% → 0.42 52% → 0.86 100%`).

## 표 밀도 · 컬럼 예산 (운영 콘솔)

`Table`은 `overflow-x-auto` 안에 있어 **컬럼 폭 합이 `minWidth`를 넘으면 마지막 열이 조용히
잘린다.** 스타일링보다 이 예산을 지키는 게 중요하다.

- 기본 `minWidth = 760`. 1440px 뷰포트에서 사이드바 244 + 본문 좌우 패딩 64 + 카드 패딩 40을
  빼면 실제 컬럼 폭이 약 1090px이고, `max-w-[1400px]` 제한 아래에서도 안전한 값이다.
- **열 상한 6개.** 실제 사용:
  - 데이터 관리 표 6열 / `minWidth 900` — 이름, 분류, 구역, 온누리, 출처, 상태
  - 보정 이력 표 5열 / `minWidth 820`
  - 오류 신고 표 6열 / `minWidth 940`
  - 콘텐츠 표 5열 / `minWidth 880` — 첫 열에 54px 썸네일 + 12px 간격이 붙어 820에서 올렸다
- 열이 넘칠 때는 **값을 보조 줄로 내려 열 수를 줄인다.** 데이터 관리 표가 관리번호를
  이름 칸 아래, 상대 위치를 구역 칸 아래, 기준일을 출처 칸 아래로 내린 것이 그 처리다.
- 좌우 높이가 다른 그리드에는 `items-start`를 준다(대시보드의 2단 그리드 2개 모두 적용).

## 콘텐츠 등록 폼 (운영 콘솔)

`오류 신고 / 콘텐츠` 화면의 `콘텐츠 등록` 버튼은 신고 상세와 같은 `Drawer`를 연다. 등록하면
화면 상태로만 목록 맨 위와 `콘텐츠 수정 이력` 타임라인에 즉시 쌓인다(목업이므로 서버 없음).

- **대표 사진은 축제일 때만 필수.** 축제는 목록 카드와 상세 히어로 두 곳에 사진 자리가 있어
  비면 미완성으로 보인다. 배너와 추천 카드는 사진 없이 나가는 형식이라 아이콘 타일을 쓴다.
  표의 첫 열도 같은 규칙으로 썸네일 또는 아이콘 타일을 보여준다.
- **`PhotoField`(`components/admin/photo-field.tsx`)는 `Field`로 감싸지 않는다.** `Field`는
  `<label>`이라 그 안에 숨은 `<input type="file">`을 두면 라벨 어디를 클릭해도 파일 선택창이
  열린다. 그래서 이 컴포넌트만 제목과 힌트를 직접 그린다.
- 업로드한 파일은 `URL.createObjectURL`로 미리보기만 하고 아무 데도 보내지 않는다. 사진을
  바꾸거나 지울 때 이전 objectURL을 `revokeObjectURL`로 반납한다.
- 보관함 썸네일은 **사진 매핑 표에서 이미 눈으로 확인한 id만** 올린다. 여기에 무작위 seed를
  넣으면 캡션과 어긋난다.
- 업로드본은 `blob:` URL이라 `next/image`로 최적화할 수 없다. 이 두 자리(미리보기, 표 썸네일)만
  `<img>`를 쓰고 이유를 주석으로 남겼다.

## Motion

- 화면 전환: `.cp-screen-in` **fade만**, `260ms cubic-bezier(.16,1,.3,1)`. 탭 전환과 상세
  진입에 같은 트랜지션을 쓴다. `transform`을 쓰지 않는 이유는 위 "화면 전환 애니메이션에
  `transform` 을 쓰지 않는 이유" 절에 있다.
- 콘솔 화면 진입, 드로어: `.cp-enter` `y: 6 → 0` + fade, `420ms cubic-bezier(.16,1,.3,1)`
  (웹 콘솔 레퍼런스 타이밍 그대로).
- 현재 위치 핀: `.cp-pulse` 정확도 원이 2.4초 주기로 확산. **색이 아니라 맥동으로**
  "지금 여기"를 전달한다.
- 도보 경로: `.cp-route-flow` 흰 파선이 출발지에서 목적지 방향으로 흐른다(1.6초 linear).
- 프레스 피드백: 카드 `active:scale-[0.985]`, CTA `active:scale-[0.98]`, 콘솔 버튼
  `active:scale-[0.99]`.
- `prefers-reduced-motion: reduce`에서 위 애니메이션 4종을 전부 `animation: none`으로
  끈다(`styles/civicpin.css` 하단). 워크스페이스 전역 CSS의 감속 규칙과 이중으로 걸려 있다.

## 시점 (mock 데이터의 "오늘")

전 화면의 기준 시점은 **2026. 06. 12 (금) 15:24**(QR 스캔 시각)이고, 데이터에 등장하는 모든
날짜는 **2026년 3월 ~ 7월** 안에 있다. 요일 표기는 실제 2026년 달력과 맞춰 두었다
(06. 11 목 / 06. 13 토 / 06. 05 금 / 06. 21 일 / 06. 19 금 / 07. 04 토 / 04. 11 토).

시점이 초여름이라 계절을 타는 문구도 함께 맞췄다. 정류장 쉼터는 한파쉼터가 아니라
**그늘막쉼터**이고, 홈 공지는 **무더위쉼터 확대 운영**, 축제는 초여름 축제 / 밤마실 야시장 /
제철 과일 장터 / 오일장 찻집 거리다. 날짜만 옮기고 계절 문구를 두면 6월에 한파쉼터를
안내하는 화면이 되므로, 날짜를 바꿀 때는 이 문구들을 같이 확인한다.

관리자 대시보드의 등록 추이는 1월 ~ 6월이고 6월이 강조 막대(집계 12일까지)다.

## 가명 처리 (spec.md 8절 반영 결과)

- 지자체 `OO시`, 행정동 `△△동`, QR 코드 `QR-△△-12`, 구역 코드 `ZONE-A1` ~ `ZONE-D3`
- 상점가 `A~D 골목형 상점가`, 매장은 `유형 + 위치` 조합(`A 시장 입구 청과상회`)
- 주소는 **행정동만 익명 표기하고 도로명과 건물번호는 실주소처럼** 쓴다
  (`△△동 시장로3길 11`). 매장, 시설, 축제 행사장 전부 `address` 필드를 가진다.
- **위치를 보여주는 자리에는 반드시 주소가 들어간다.** 상대 위치
  (`상점가 내 3구역, 뒷길 모퉁이`)만 쓰는 화면은 두지 않는다 — 처음 온 사람은 "3구역"이
  어디인지 알 수 없다. 공간이 있는 상세 화면은 `주소 + 상대 위치` 두 줄, 목록 행처럼 한 줄만
  들어가는 자리는 주소만 쓴다.

  | 자리 | 표기 |
  |---|---|
  | 매장 상세 "위치", 지도 시설 상세 | 주소(첫 줄) + 상대 위치(보조 줄) |
  | 축제 상세 "장소" | 장소 이름 + 주소(보조 줄) |
  | 홈/지도/상점가 목록 행, 길찾기 도착지 | 주소만 |
  | 관리자 데이터 표 | `구역 \| 주소` + 상대 위치(보조 줄), 편집 폼에 주소 입력란 |

- 도로는 다섯 개뿐이다. A 상권 본길 `시장로`(1구역 12번 → 4구역 72번), A 3구역 뒷길
  `시장로3길`, 간선도로 `중앙로`(정류장, 주민센터, 학교), 공원 일대 `공원로`,
  B/C/D 상권 `하천로` / `단지로` / `장터로`.
- 건물번호는 입구에서 안쪽으로 커지고 홀수/짝수를 길 양편으로 갈라 뒀다. 국밥집이 41번,
  "국밥집 맞은편" 생활잡화점이 44번인 식이라 상대 위치 문구와 주소가 서로 어긋나지 않는다.
  공영주차장 AED와 화장실은 같은 부지라 같은 번호(72)를 쓴다.
- 운영자 이름(정하윤, 남기헌, 서지완), 신고자 마스킹(`사용자 8**2`)은 실존하지 않는 가상값
- 통계 수치는 유사 범위의 임의값. 대시보드의 누적 신고 34건과 신고 표의 최근 8건은 **의도적으로
  다른 집계**이고, 화면에 "누적 34건" / "최근 접수 8건"으로 명시해 숫자가 어긋나 보이지 않게 했다
