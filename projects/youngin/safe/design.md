# 용인 SAFE — Design

용인시 생활안전 대응 훈련 콘텐츠(모바일 웹, 시뮬레이션 게임형)의 디자인 결정 기록.
`spec.md`의 사용자용 화면 3종(미션 선택 / 실제 상황 대응 게임 / 미션 결과 리포트)이 대상이다.

## 적용 규칙

- `spec.md`에 `스타일:` / `디자인시스템:` / `프리미엄디테일:` 줄이 없어 **스타일 배리언트 스킬과
  design-system 문서는 적용하지 않았다.** 워크스페이스 `CLAUDE.md`의 UI Generation Rules를
  1순위로 두고, 그 밖의 판단은 `supanova-design-engine`의 디자인 판단만 가져왔다
  (표준 HTML 출력 규약은 이 워크스페이스와 충돌하므로 따르지 않음).
- 구조적 값(8px 그리드, 타입 스케일, radius, 안전 영역 top 59 / bottom 34, 44x44pt 터치 타깃,
  스프링 타이밍)은 `_reference-design-system.md`와 `_reference-styles/filmate.css`를 그대로 따랐고,
  색상은 전부 새로 정의했다.
- 다이얼: `DESIGN_VARIANCE 7` / `MOTION_INTENSITY 5` / `VISUAL_DENSITY 5`.
  - VARIANCE를 기본값 8보다 낮춘 이유: 학교, 경로당, 주민센터 배포용 공공 콘텐츠라
    화면마다 레이아웃 문법이 튀면 처음 쓰는 사람이 길을 잃는다. 대신 화면 3종의
    **재질**(종이 캔버스 / 딥 맵 / 딥 히어로 + 종이 본문)을 크게 다르게 가져가 리듬을 만들었다.
  - MOTION을 낮춘 이유: 이 콘텐츠의 모션은 거의 전부 **상태 전달용**이다. 골든타임 카운트다운,
    경로 진행, AED 분석 대기. 장식 모션은 넣지 않았다.
  - DENSITY를 올린 이유: 게임 화면이 지도, HUD, 단계 트래커, 선택지를 한 화면에 동시에
    보여 줘야 한다. 리포트도 점수 3축 + 단계별 시간 + 체크리스트를 담는다.

## Tokens / 팔레트

색상 축은 **따뜻한 종이 캔버스 + 비상구 그린 액센트**다. 한국의 비상구, AED, 대피소 표지가
전부 초록이라 "안전 시설 = 초록"을 그대로 브랜드 축으로 삼았다. 그 대신 빨강, 앰버, 파랑,
슬레이트는 브랜드가 아니라 **시나리오 구분용 의미색**으로만 쓴다. 액센트는 초록 하나다.

## Shape

- radius 스케일: 칩과 배지 `full` / 버튼과 선택지 `12px` / 카드 `14~16px` /
  큰 패널과 액션 시트 `20px` / 기기 화면 `50px`(`PhoneFrame` 고정값).
- shadow 정책: 종이 캔버스 위에서만 미세한 1단 그림자
  (`0 1px 2px rgba(23,21,18,0.04)`), 선택된 카드는 그림자 대신
  `0 0 0 3px var(--sf-accent-soft)` 링. **딥 서페이스 위에서는 그림자를 쓰지 않고
  `--sf-deep-line` 1px 보더로만 층을 나눈다.** 어두운 면에 그림자를 얹으면 탁해진다.
- 지도 건물 블록만 예외적으로 2.5D 두께를 준다. 같은 사각형을 `(x+2, y+3)`에 `#0E1814`로
  한 번 더 깔아 만든 그림자이며, 필터가 아니라 도형이라 비용이 없다.

## Typography

Pretendard 고정. 레퍼런스의 Apple HIG 스케일을 그대로 쓴다.

| Role | Size / Line | Weight | 쓰는 곳 |
| --- | --- | --- | --- |
| Display | 34 / 41 | 700 | 미션 선택 진입 문장 |
| Score | 56 / 58 | 700 | 리포트 점수 |
| Timer | 33 / 37 | 700 | 게임 HUD 골든타임 |
| Title 1 | 24 / 29 | 700 | 추천 미션 카드 제목 |
| Title 2 | 17~19 / 23~24 | 600~700 | 섹션 제목, 액션 패널 질문 |
| Body | 13.5~15 / 19~22 | 400~600 | 본문, 선택지 |
| Callout | 11.5~12.5 / 16~18 | 500~600 | 캡션, 메타, 힌트 |
| Micro | 10~11 / 14 | 700 | 배지, 아이브로우, 범례 |

- **`.sf-num`(`font-variant-numeric: tabular-nums`)를 시간, 거리, 점수, 반응시간에 전부 건다.**
  골든타임이 1초마다 자릿수 흔들림 없이 줄어야 게임처럼 읽힌다.
- `.safe` 스코프에 `word-break: keep-all; overflow-wrap: break-word`를 걸어 한글이 단어 중간에서
  끊기지 않게 했다.
- em dash(—)와 중간점(·)은 렌더링되는 모든 문자열에서 쓰지 않는다. 이 프로젝트에서
  이질적인 메타 필드를 잇는 자리는 전부 파이프(`3층 사무실 입구 | 90m | 도보 0:56`)를 쓴다.

## 벡터 지도 시스템 (프로젝트 고유)

`components/city-map.tsx`는 용인 처인구 김량장동 일대를 손으로 그린 SVG다. 외부 지도 API나
위성 이미지를 쓰지 않는다 (스크린샷 품질이 일정해야 하고, 용인이 아닌 사진을 깔면 스펙의
"우리 동네 체감도"가 무너진다). 실제 측량이 아니라 **금학로, 중부대로, 경안천의 관계와
시청, 중앙시장, 행정복지센터, 초등학교의 상대 위치를 유지한 스타일라이즈드 맵**이다.

- 좌표계는 **`viewBox 0 0 393 300` 하나로 고정**한다. 시설 핀 좌표(`lib/mission-data.ts`)도
  같은 계에서 정의하므로 지도와 데이터가 어긋날 수 없다.
- 이 비율은 게임 화면에서 HUD(약 224px)와 액션 패널(`min-h-[326px]`, `-mt-5` 겹침)을 뺀
  **실제 지도 밴드(393 x 약 300)** 에 맞춘 값이다. `preserveAspectRatio="xMidYMid slice"`이므로
  **밴드가 세로로 길어지면 좌우가, 짧아지면 상하가 잘린다.** 액션 패널 높이를 바꾸면
  `VIEW_H`도 같이 본다.
- 액션 패널 높이가 단계마다 흔들리지 않도록 판단 피드백 배너와 이동 상태 카드는
  패널이 아니라 **지도 위 오버레이**에 쌓는다.
- 핀 라벨은 `y > 200`이면 핀 위에, 아니면 아래에 단다. 아래에 달면 하단 범례 스트립에 가린다.
- 라벨은 `paintOrder: stroke` + `stroke: var(--sf-deep)`로 지도 위에서 읽히게 한다.
- 현재 위치 확산 링(`.sf-ping`)에는 **`transform-box: fill-box`가 반드시 필요하다.** SVG의
  `transform-box` 기본값은 `view-box`라, 지정하지 않으면 링이 자기 중심이 아니라 viewBox
  중심을 기준으로 커지면서 핀에서 떨어져 나간 유령 원으로 보인다.
- 범례는 지도 하단 가로 스트립 하나로 고정한다. AED, 무더위쉼터, 한파쉼터, 옥외대피장소
  네 종류를 항상 함께 보여 줘서 "이 지도가 실제 공공데이터"라는 사실을 화면에 남긴다.

## 점수 체계 (프로젝트 고유)

리포트가 "학습했다"는 신뢰를 주려면 점수의 근거가 화면에 있어야 한다. `lib/scoring.ts`의
점수는 세 축의 합이고, 리포트 히어로에 세 축을 그대로 게이지로 보여 준다.

- **행동 정확도 60점** — 판단 지점 정답률.
- **대응 속도 25점** — 제한시간(270초) 대비 여유. 만점 기준은 무결점 완주 시간 239초.
- **반응 속도 15점** — 선택지가 뜨고 실제로 탭하기까지 걸린 시간. 1초 이하 만점, 3.5초 이상 0점.

대응 시간과 반응 시간은 **서로 다른 지표**다. 대응 시간은 시뮬레이션상 경과 시간
(신고 22초, 탐색 18초, 이동 131초, 사용 68초 + 오답 페널티)이고, 반응 시간은 플레이어가
실제로 화면을 보고 판단하는 데 걸린 실측 시간이다. 스펙이 둘을 나눠 요구하므로 나눠서 잰다.

게임을 거치지 않고 리포트 화면만 열었을 때는 `SAMPLE_RESULT`(오답 1개가 섞인 완주 기록)를
쓴다. 개선 포인트 섹션이 비면 이 화면의 핵심이 사라지기 때문이다.

## 기기 프레임 안쪽 규칙

- **엣지 고정 UI에 `backdrop-blur`를 쓰지 않는다.** 미션 선택과 리포트의 하단 액션 바
  (`BottomBar`)는 `bg-[var(--sf-surface)]` 불투명, 게임 화면의 HUD와 액션 패널은
  `bg-[var(--sf-deep)]` / `bg-[var(--sf-deep-raised)]` 불투명이다. 반투명 채움도 쓰지 않는다.
  Chromium에서 backdrop-filter는 `PhoneFrame`의 `rounded-[50px]` 클립을 뚫고 모서리에
  흰 틈을 만든다.
- 하단 바는 화면 박스 안쪽 `absolute inset-x-0 bottom-0`이다. `fixed`나 음수 offset은 쓰지 않는다.
- **`sf-enter` 같은 transform 애니메이션을 하단 바의 조상에 걸지 않는다.** transform은 그
  요소를 absolute 자식의 컨테이닝 블록으로 만들어, 하단 바가 화면 하단이 아니라
  스크롤 콘텐츠 끝에 붙어 버린다. 진입 애니메이션은 `BottomBar`를 감싸지 않는
  안쪽 래퍼에만 건다 (미션 선택, 리포트 두 화면 모두 이 구조).
- 안전 영역: 상단 `pt-[59px]`(콘텐츠는 `pt-[67~71px]`), 하단 바 `pb-9`(36px, 홈 인디케이터 34pt).
- 게임 화면은 `h-[852px]` 고정 flex 컬럼이라 스크롤이 없다. 지도가 스크롤에 딸려 움직이면
  게임이 아니다.
- 상태바 잉크는 화면마다 뒤집는다. 게임은 항상 `#F1EFE8`, 미션 선택은 항상 `#171512`.
  리포트는 딥 히어로가 상태바 아래 남아 있는 동안만 밝은 잉크를 쓰고, 스크롤해서 종이 캔버스가
  올라오면 어두운 잉크로 되돌린다 (`ReportScreen`이 스크롤 컨테이너를 찾아
  `onHeroVisibleChange`로 알린다). 고정하면 스크롤 후 상태바가 배경에 묻힌다.

## Motion

| 대상 | 값 | 목적 |
| --- | --- | --- |
| 화면 진입 `.sf-enter` | 260ms `cubic-bezier(.16,1,.3,1)`, `translateY 10 → 0` | 화면 전환 |
| 액션 패널 `.sf-panel-in` | 300ms 같은 이징, `translateY 18 → 0` | 단계가 넘어갔다는 신호 |
| 리스트 스태거 `.sf-stagger` | 280ms + `--sf-i * 55ms` 지연 | 선택지가 순서대로 들어옴 |
| 현재 위치 `.sf-ping` | 2000ms 무한, `scale .4 → 2.1` | 위치 갱신 중 |
| 골든타임 경고 `.sf-urgent` | 900ms 무한 opacity | 남은 시간 60초 이하 |
| 경로 점선 `.sf-route-flow` | 900ms linear `stroke-dashoffset` | 이동 방향 |
| AED 분석 `.sf-analyze` | 1400ms 왕복 `translateX` | 기기가 리듬을 분석 중 |
| 이동 진행 | `requestAnimationFrame`, 시뮬레이션 131초를 실제 5.6초로 압축 | 거리와 시계가 함께 줄어드는 것을 보여 준다 |
| 버튼 프레스 | `active:scale-[0.98]`(주요), `[0.985]`(카드와 선택지) | 탭 피드백 |

- 애니메이션은 `transform`과 `opacity`만 건드린다. 진행 게이지의 `width` 전환만 예외이고,
