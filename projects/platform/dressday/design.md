# DRESSDAY 디자인 문서

고객용 반응형 웹(`/platform/dressday`)과 관리자 웹(`/platform/dressday-admin`)이 이 문서 하나를 쓴다.
관리자 화면 코드는 이 프로젝트의 `components/admin/`에 있고, `dressday-admin`은 URL을 하나 더 얻기 위한
얇은 엔트리다. 관리자는 이 프로젝트의 토큰(`styles/dressday.css`)을 그대로 상속하며 자체 문서가 없다.

## 아키타입

**홈 골격: 검색 우선** (`mockup-craft` web.md 어휘). 관리자 셸 **C4 아이콘 레일 + 섹션 리스트**.
팔레트 구성 **1 단일 액센트 / 라이트 뉴트럴**.

- **홈 골격 이유.** 이 서비스의 첫 질문은 "무슨 옷"보다 "언제, 어디로 받느냐"다. 당일 배송은 주소와
  주문 마감 시각에 따라 되고 안 되고가 갈린다. 그래서 히어로 자리를 큰 검색 바(받는 날, 받는 곳, 사이즈)에
  준다. 디자인시스템(airbnb_compact)의 search-bar-pill과 search-orb가 이 골격을 전제로 만들어져 있다.
  - 이어지는 블록은 서로 다른 레이아웃으로 조합했다:
    카테고리 탭 + 조건 목록(오늘 받을 수 있는 옷, 4열) → 가로 레일(인기, 페이지에서 1회) →
    편집 그리드(신규, 크기가 다른 카드) → 이용 흐름(4단계, 숫자 없음) → 배송 가능 지역(구별 마감 시각 목록).
  - 배제 1, **풀블리드 미디어 히어로**: 상품 사진이 6장뿐이라 첫 화면을 사진 한 장에 맡길 수 없다.
    배송 조건을 먼저 묻는 서비스 성격과도 맞지 않는다.
  - 배제 2, **좌정렬 분할 히어로**: 카피와 사진이 주인공이 되는 브랜드 쇼핑몰 문법이다. 렌탈 가능 여부를
    확인하는 검색보다 아래로 밀린다.
- **셸 이유 (C4).** 관리자 화면 9개가 운영, 배송, 상품, 고객 네 묶음으로 자연스럽게 나뉜다(섹션 4개, 각 2~3개 뷰).
  - 배제 C1: 운영자가 내부 관리자라 C1 조건에 맞지만, 같은 `platform/` 카테고리에 이미 veli-admin과
    studyspot-hq가 C1이다 (같은 카테고리 중복 금지).
  - 배제 C3: 상단 주내비 상한이 5개라 9개 뷰를 담지 못한다.
  - C4의 섹션 리스트 칸에는 그 섹션에서만 의미 있는 숫자를 둔다: 운영 = 미배차 건수, 배송 = 지연 건수,
    상품 = 검수 대기 벌, 고객 = 이번 달 매출.
- **이 골격에서 쓰지 않는 부품**
  - `SectionHead(제목 + 더보기)` 반복. 섹션 제목 오른쪽에는 링크 하나까지만, 모든 섹션에 붙이지 않는다.
  - 가운데 정렬 히어로 + 같은 카드 3열 + CTA 띠
  - 섹션 위 영어 아이브로우, "이렇게 이용하세요" 식 설명 섹션의 반복
  - 하단 탭바 (웹이다. 모바일은 헤더 + 메뉴 시트)
  - 관리자: 236px 라벨 레일, 전폭 `h-14` 헤더, 264px 드로어, 헤더 우측 시계

해석: 여성의류 당일 렌탈 사이트 for 오늘 저녁 하객룩이나 면접 옷이 급한 20~30대 여성. 다이얼 V6 / M5 / D4 (홈 기준).

- **읽은 skill**: `mockup-craft` SKILL.md, references/anti-slop.md, references/web.md, references/console.md

- **디자인시스템**: `design-systems/airbnb_compact.md`. 색, 타입 스케일, radius, 그림자 한 단계,
  컴포넌트 치수(검색 바 64, orb 48, 버튼 48, 입력 56, 날짜 셀 40)의 출처다. 폰트는 CLAUDE.md에 따라 Pretendard.
- 다이얼은 SKILL.md 2절 프리셋 표에서 출발했다.
  - 홈 V6 / M5 / D4: 표 그대로. 블록마다 처리 방식이 다르다(탭 + 그리드, 레일, 비대칭 그리드, 흐름, 목록).
    모션은 히어로 진입과 섹션 진입 1회뿐이라 M5 상한에서 멈춘다.
  - 상품 탐색 V4 / M3 / D6: 표 그대로. 필터와 그리드가 정형이어야 비교가 된다.
  - 상품 상세 V5 / M4 / D4: 표 그대로. 갤러리 + sticky 예약 카드.
  - 예약, 결제 V3 / M3 / D4: 표 그대로. 한 열 폼 + 금액 요약.
  - 예약 조회, 반납 V4 / M4 / D4 (표에 없음): 현재 단계 하나를 크게 두는 상태 화면이라 V를 예약보다 한 칸 올렸다.
  - 관리자 목록 V3 / M2 / D8, 대시보드 V4 / M3 / D7: 콘솔 표 그대로.

## Shape

airbnb_compact 그대로: 버튼 8, 카드와 사진 14, 검색 바, 하트, orb, 칩은 완전한 원형 끝, 카테고리 탭 아이콘 영역 32.
관리자 패널 14, 입력과 버튼 8. 그림자는 `card-float` 하나만(검색 바 기본 상태, 예약 카드, 드롭다운, 시트).
사진 비율: 상품 카드 **3:4** (디자인시스템의 1:1 숙소 카드 대신, 의류는 세로가 맞다), 편집 그리드 큰 카드 4:5.

## Typography

- 디자인시스템 타입 스케일(Pretendard 대체)을 쓴다. 본문 **16 / 24 / 400** (body-md), 보조 14 / 20 (body-sm).
  - "스케일 복제 금지" 1번(본문 크기)은 **디자인시스템 지정**이다. 직전 logisync는 14 / 20이다.
- 홈 h1은 디자인시스템대로 28 / 40 / 700. 무게는 사진과 검색 바가 진다. 64px는 쓰지 않는다
  (디자인시스템이 평점 표시 하나에만 허용하고, 이 서비스에 평점 대형 표시는 없다).
- 페이지 제목 22 / 26 / 500 (display-lg), 가격 21 / 30 / 700 (display-md), 카드 제목 16 / 20 / 600.
- 700은 화면당 h1과 가격 하나. 숫자(가격, 시각, 수량)는 `tabular-nums`, 큰 숫자에 단위를 붙이지 않는다:
  상세의 가격은 `대여료 (1일)` 라벨 + `39,000원`처럼 표기하고, 관리자 지표는 `오늘 예약 (건)` 라벨 + 숫자만.
  - 쇼핑 가격의 `원`은 가격 표기 관례라 유지한다. 관리자 지표와 표 숫자 열에는 단위를 붙이지 않는다.
- 관리자: 표 본문 14 / 20, 표 헤더 13 / 500, 페이지 제목 22 / 500, 지표 숫자 28 / 600 (weight 600, 기본 자간).
- 관리자 코드(예약번호 `DD-0918-2471`, 재고 태그 `WD-0231-03`)만 모노(`.dd-code`).

## 반응형 기준

기준 폭: 393(모바일), 768(`md`), 1024(`lg`), 1440(데스크톱). 디자인시스템 분기점(744, 1128)은
Tailwind 기본 `md`, `lg`로 맞췄다. 모바일 우선. 본문 폭 `max-w-[1280px]`(디자인시스템 에디토리얼 캡),
좌우 여백 모바일 24, `lg` 이상 32. 페이지 가로 스크롤 0.

| 영역 | 데스크톱 | 모바일 |
| --- | --- | --- |
| 헤더 | 80px 한 줄: 워드마크, 메뉴 3, 배송지 칩, 저장, 계정 | 64px: 워드마크, 검색, 메뉴 버튼 → 오른쪽 시트 |
| 홈 검색 바 | 64px 알약 3분할(받는 날, 받는 곳, 사이즈) + orb 48 | 한 줄 버튼 → 조건 3줄 카드로 펼쳐 둔다 |
| 홈 조건 목록 | 4열 | 2열 |
| 인기 레일 | 5장 보이는 가로 레일 | 2.3장 보이는 가로 레일 (페이지당 1회) |
| 편집 그리드 | 큰 카드 1 + 작은 카드 4 (2x2) | 큰 카드 1 + 작은 카드 2열 |
| 이용 흐름 | 4열 | 세로 목록 |
| 탐색 | 좌측 필터 248 + 결과 3열 | 상단 필터 버튼 → 바텀 시트, 결과 2열 |
| 상세 | 갤러리 58% + sticky 예약 카드 | 갤러리 → 정보 → 하단 고정 바(가격 + 예약하기, 불투명) |
| 예약, 결제 | 폼 + 우측 sticky 금액 요약 | 폼 → 금액 요약 → 하단 고정 CTA |
| 예약 조회, 반납 | 현재 단계 + 타임라인 2열 | 1열 |
| 마이페이지 | 좌측 메뉴 + 내용 | 메뉴가 가로 스크롤 탭 |

- 터치 타깃 모바일 44 이상. 하단 고정 바는 불투명 흰색 + 위 경계선, blur 없음.
- 화면 높이는 `min-h-[100dvh]`.

## 셸 레이아웃 (관리자, C4)

- 1열: 64px 아이콘 레일, 흰 바탕 + 오른쪽 경계선. 활성 섹션만 잉크 채움 원(40) + 흰 아이콘(fill).
- 2열: 섹션 리스트 232px, `--dd-soft` 바탕. 섹션 제목 20 / 600, 하위 뷰 목록, 아래에 섹션 요약 블록 하나.
- 3열: 헤더 60px는 이 열 위에만 얹힌다. 좌측 브레드크럼(섹션 / 뷰), 가운데 전역 검색(예약번호, 고객, 재고 태그),
  우측 알림과 계정. 본문 `max-w-[1320px]`, 좌우 32.
- `lg` 미만: 레일이 하단 아이콘 바(불투명)로 내려가고, 섹션 리스트는 본문 위 가로 스크롤 세그먼트가 된다. 드로어 없음.
- 고객 사이트와 관리자 셸은 공유하지 않는다. 고객 화면에는 관리자 진입점이 없다.

## 표 밀도, 컬럼 예산

- 1440 폭에서 본문 = 1440 − 64 − 232 − 64(좌우 여백) = **1080px**.
- 표 셀 세로 패딩 12, 가로 16. 행 높이 약 52(두 줄 셀 64).
- 열 상한 6. 기본 `minWidth` 960, 넘치면 보조 정보를 이름 아래 두 번째 줄로 내리고 열을 줄인다.
- 숫자 열 오른쪽 정렬 + `tabular-nums`, 헤더에 단위: `대여료 (원)`, `보증금 (원)`.
- 좌우 높이가 다른 그리드에는 `items-start`.

## Motion

"스케일 복제 금지" 2, 3번. 직전 logisync(180ms 거의 선형 + 가로 이동, 배경 톤 눌림)와 다르게 골랐다.

- 화면 진입: **280ms `cubic-bezier(.2,0,0,1)`** (감속형) + opacity + `translateY(12px)`. 화면이 바뀐 것을 알린다.
- 홈 첫 진입 스태거: 히어로 요소 4개, 50ms 간격, 1회. 섹션 진입은 `IntersectionObserver`로 섹션당 1회.
- 시트, 모바일 메뉴: 320ms 같은 곡선, 아래(또는 오른쪽)에서.
- 눌림 피드백: **`scale(0.98)`** + 디자인시스템 active 색(Rausch → `#e00b41`). 이유: 버튼이 눌렸다는 촉감.
  디자인시스템의 no-hover 정책에 따라 hover 효과는 두지 않는다. 예외는 상품 사진 확대(데스크톱, 카드 사진만).
- 관리자: 드로어와 드롭다운 220ms 같은 곡선. 표 행과 지표는 등장 애니메이션이 없다.
- 무한 반복은 조회 화면의 "이동 중" 점 하나(1.8s 투명도)만. 실제 진행 중 상태를 알리는 기능이다.
- `prefers-reduced-motion: reduce`에서 진입, 스태거, 시트 전환, 점 펄스를 모두 끈다.
