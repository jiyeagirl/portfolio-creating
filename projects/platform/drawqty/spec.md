# DrawQty Product Spec

## 1. Overview

DrawQty는 건설사가 시스템비계·시스템동바리 업체 홈페이지에서 건축 DWG 도면을 업로드하면 개략 물량(비계 설치 면적 ㎡, 동바리 RC·DECK 체적 ㎥)이 자동 산출되고, 그 결과로 바로 견적을 요청할 수 있는 웹 서비스다. 정밀 구조계산이나 3D 모델링이 아니라 견적 검토용 개략 물량을 빠르게 보는 것이 목적이다. 자동 인식이 어려운 부분은 사용자가 구간·높이·면적을 직접 지정하거나 수정한다.

이 프로젝트는 위시켓 공고(DWG 도면 인식 기반 물량 산출·견적 요청 웹 프로그램)의 핵심 기능 5개를 화면으로 보여 주는 **포트폴리오용 목업**이다. 실제 DWG 파싱, 자동 인식, 서버 저장, 엑셀 생성은 만들지 않고, 화면과 흐름만 목업 데이터 위에서 끝까지 이어지게 한다.

- **플랫폼**: Web. 건설사용 사용자 화면 4개와 관리자 화면 1개.
- **연동 표현**: 사용자 화면 상단에 "기존 업체 홈페이지에 연동된 모습"을 보여 주는 가상 홈페이지 헤더(로고, 회사 소개·시공 사례·견적 문의 메뉴)를 얹고, 그 아래 본문에 물량 산출 기능이 들어 있는 형태로 만든다. 관리자 화면은 별도의 관리자 콘솔 헤더를 쓴다.
- **사용자**: 건설사 담당자(고객)와 업체 관리자 2종류. 첫 화면 우측 상단에 "사용자 화면 / 관리자 페이지" 전환 스위치를 둔다.
- **데이터**: 전부 목업 데이터. 백엔드, 로그인, 실제 파일 처리는 없다. 상태 변경은 화면 안 컴포넌트 상태로만 처리하고, 사용자 화면에서 한 업로드와 견적 요청이 관리자 화면에 그대로 반영된다.

## 2. Information Architecture

사용자 화면 상단에 4단계 진행 표시(① 도면 업로드 → ② 인식 확인·수정 → ③ 물량 결과 → ④ 견적 요청)를 두고 단계 순서로 이동한다. 관리자 화면은 별도 내비로 접근한다.

1. **도면 업로드** (`upload`)
   - DWG 파일 드래그 앤 드롭 / 파일 선택 영역(목업이므로 파일을 올리거나 "예시 도면으로 체험하기" 버튼을 누르면 샘플 도면이 올라간 것으로 처리)
   - 도면 종류 선택: 건축도면 / 구조도면, 산출 대상 체크: 시스템비계 / 시스템동바리
   - 업로드 진행 바와 파일 정보(파일명, 크기, 층수, 인식된 도면 레이어 수)
   - 안내 문구: "개략 물량 산출용이며 정밀 구조계산 결과가 아닙니다"
   - "물량 산출 시작" 버튼을 누르면 분석 진행 화면(단계별 문구 "도면 레이어 분석 → 외벽·슬래브 인식 → 층고 반영")이 2~3초 보이고 인식 확인 화면으로 이동
2. **인식 확인·수동 지정** (`review`)
   - 중앙에 도면 뷰어(평면도를 SVG로 그린 목업): 자동 인식된 외벽 구간(비계 대상)과 슬래브 영역(동바리 대상)이 색으로 표시됨
   - 층 선택 탭(1F, 2F, 3F, RF)과 확대·이동 컨트롤
   - 우측 패널에 인식 결과 목록: 구간별 길이·높이·면적, 슬래브별 면적·내부 높이
   - 수동 수정: 목록 행을 누르면 높이·면적 값을 입력해 수정할 수 있고, 인식이 안 된 곳은 "구간 추가"로 도면 위에 사각형 영역을 그려 지정(목업이므로 정해진 위치에 영역이 추가되는 연출)하고 높이를 입력
   - 인식 신뢰도 배지: 높음(초록) / 확인 필요(주황, 사용자 확인을 유도)
   - 수정할 때마다 하단 요약 합계가 즉시 갱신
3. **물량 산출 결과** (`result`)
   - 요약 카드 2개: 시스템비계 설치 면적(㎡), 시스템동바리 체적(㎥, RC / DECK 구분)
   - 층별 상세 표: 층, 구분, 대상, 길이·면적·높이, 수량. 숫자는 우측 정렬, 천 단위 구분, 소수점 1자리
   - 층별 비교 막대 차트
   - "엑셀로 내보내기" 버튼(목업이므로 눌렀을 때 다운로드 완료 토스트만 표시), "수정하러 돌아가기", "견적 요청하기" 버튼
   - 하단 고정 문구로 개략 물량 안내
4. **견적 요청** (`quote`)
   - 입력 폼: 업체명, 현장명, 담당자명, 연락처, 이메일(선택), 공사 예정 시기, 요청 메모
   - 우측에 산출 결과 요약 카드(도면 파일명, 비계 면적, 동바리 체적)
   - 필수 항목 검증과 개인정보 수집 동의 체크
   - "견적 요청" 버튼을 누르면 접수 완료 화면(접수번호, 안내 문구, "새 도면 업로드" 버튼)으로 바뀌고, 관리자 화면의 목록 첫 줄에 추가됨
5. **관리자 페이지** (`admin`)
   - 탭 2개: **견적 요청 목록** / **업로드 도면**
   - 견적 요청 목록: 접수번호, 업체명, 현장명, 연락처, 요청일, 비계 면적, 동바리 체적, 처리 상태(신규 / 검토 중 / 견적 발송). 행을 누르면 우측 패널에 고객 정보 전체와 산출 요약, 상태 변경 버튼
   - 업로드 도면: 파일명, 업로더(업체명), 업로드 일시, 크기, 인식 결과(정상 / 수동 수정 포함). 행을 누르면 도면 뷰어 미리보기와 산출 결과 요약을 보여 줌
   - 업체명·현장명 검색

## 3. Key Focus

- **업로드부터 견적 요청까지 한 바퀴**: 업로드 → 인식 확인·수정 → 결과 → 견적 요청 → 관리자 목록 확인이 목업 데이터 위에서 끝까지 이어져야 한다.
- **도면 인식 화면이 가장 중요**: 도면 위에 인식 구간이 색으로 겹쳐 보이고, 목록과 도면이 서로 연결(행을 누르면 해당 구간 강조)되며, 수정하면 합계가 즉시 바뀌어야 한다. 자동 인식과 수동 보정이 함께 있는 제품이라는 점이 한눈에 보여야 한다.
- **숫자 신뢰감**: 표와 요약의 숫자 표기(천 단위 구분, 우측 정렬, 단위 ㎡·㎥ 일관 표기)를 신경 쓴다. "개략 물량" 안내는 결과와 견적 요청 화면에 항상 보인다.
- **기존 홈페이지에 붙는 도구처럼 보이기**: 가상 홈페이지 헤더와 푸터 안에 기능이 자연스럽게 들어앉은 모습이어야 하며, 톤은 건설·산업 분야에 맞게 차분하고 정돈된 느낌으로 한다.
- **상태 색의 일관성**: 인식 신뢰도(높음 초록 / 확인 필요 주황 / 수동 수정됨 파랑)와 견적 상태(신규 파랑 / 검토 중 주황 / 견적 발송 초록)를 모든 화면에서 같은 의미와 색으로 쓴다.

## 4. Mock Data Guide

- **가상 업체**: 시스템비계·동바리 임대 업체 "한결시스템" (홈페이지 헤더용). 실제 업체명은 쓰지 않는다.
- **샘플 도면**: 지상 4층 + 옥상 규모의 근린생활시설 1동. 파일명 예시 `OO근린생활시설_건축_평면도.dwg` (약 4.2MB). 평면도는 직사각형에 가까운 건물 외곽과 내부 슬래브 구획 3~4개를 SVG로 단순하게 그린다.
- **산출 결과 예시**: 시스템비계 약 2,480㎡, 시스템동바리 RC 약 310㎥ / DECK 약 185㎥. 층별 수치는 합계가 맞도록 구성한다. 층고는 1층 4.2m, 2~4층 3.3m, 옥상 3.0m 등 층마다 다르게 둔다.
- **인식 결과 목록**: 구간 8~10개 중 신뢰도 "확인 필요" 2개, 사용자가 수정한 "수동 수정됨" 1개를 포함한다.
- **견적 요청(관리자 목록)**: 8~10건. 가상 건설사명(예: 대성종합건설, 우진건설산업), 현장명(예: 성수동 근생 신축현장), 연락처는 가상 번호(010-0000-XXXX)로 쓴다. 처리 상태가 골고루 섞이게 하고 신규 건이 3건 이상 있어야 한다.
- **업로드 도면 목록**: 견적 요청 건과 대응되는 10건 내외. 일부는 수동 수정이 포함된 건으로 표시한다.

## 5. Out of Scope

- 실제 DWG 파일 파싱, 자동 인식, 물량 계산 로직, 실제 엑셀 생성, 서버·DB, 로그인
- 정밀 구조계산, 3D 모델링, 자재 상세 수량(부재별 수량), 단가·견적 금액 자동 산출
- 결제, 회원가입, 모바일 전용 앱, 다국어
- 요구사항 정의서, DB 스키마, 운영 매뉴얼 등 문서 결과물
## 6. 구현 메모 (워크스페이스)

- **관리자는 별도 URL이다.** 사용자 화면은 `/platform/drawqty`, 관리자 페이지는 `/platform/drawqty-admin`이다. 관리자 화면 코드는 이 프로젝트의 `components/admin/`에 있고 `drawqty-admin`은 URL을 하나 더 얻기 위한 얇은 엔트리다(자체 spec, design 없음, 토큰 상속). **사용자 지시로 spec 1절의 "가상 홈페이지 헤더, 푸터"와 "전환 스위치"는 구현하지 않는다.** 실제 업체가 내부적으로 운영하는 서비스로 보고, 사용자 앱과 관리자 앱은 주소와 계정이 다른 별개 화면으로 둔다(서로 오가는 스위치와 사이트 메뉴, 푸터 없음).
- **데이터 공유.** 백엔드가 없어서 사용자 화면의 업로드와 견적 요청은 브라우저 `localStorage`(`drawqty:v1`)로 관리자 화면에 전달된다. 같은 브라우저에서 두 URL을 오가면 방금 접수한 건이 목록 첫 줄에 나타난다.
- 시작 화면과 상태는 `?screen=upload|review|result|quote`, `?state=filled|analyzing|done|toast`, `?floor=`, `?edit=`, `?add=1`(사용자), `?screen=quotes|drawings`, `?select=`(관리자)로 고른다.
