# TaxDesk design.md

사용자 웹(반응형, `/monitoring/taxdesk`)과 관리자 웹(`/monitoring/taxdesk-admin`)을 한 프로젝트에서 만든다.
관리자 화면 코드는 `components/admin/`에 있고, `taxdesk-admin`은 URL만 얻는 얇은 엔트리다. 관리자는
이 문서의 토큰을 그대로 상속하며 `-admin`에는 문서를 두지 않는다. 사용자 웹에는 관리자 진입점이 없다.

## 아키타입

**사용자 웹 홈 골격: 좌정렬 분할 히어로 + 단계 폼 (form-flow).** 홈이 따로 없고 첫 화면이 곧 신고 신청이다.
히어로는 왼쪽에 서비스 문장과 수수료, 오른쪽에 "위임장이 만들어지는 모습" 미리보기 한 장. 그 아래가 바로
4단계 신청 폼이다. 레퍼런스 삼쩜삼(첫 화면에서 바로 신청 시작, 해요체, 결과 중심 현황), 모두싸인(서명 방식
선택과 문서 미리보기), 토스 결제(금액 요약과 상태 화면).

화면별 골격 (인접 화면끼리 겹치지 않게):

| 화면 | 골격 |
| --- | --- |
| 신고 신청 | 분할 히어로 + form-flow (데스크톱 좌 단계 레일, 우 폼 / 모바일 한 화면 한 단계) |
| 증빙 제출 | 2단 워크벤치: 좌 AI 안내 대화, 우 체크리스트 슬롯 (모바일은 상단 세그먼트로 전환) |
| 위임장 서명 및 결제 | 문서 중심: 가운데 위임장 종이 미리보기가 주인공, 우측 sticky 서명/결제 패널 |
| 내 신고 현황 | 상태 조회: 현재 단계를 크게, 지난 단계는 시각 붙은 타임라인, 요약 표 |
| 알림톡 수신 | 모바일 보기 전용 iPhone 잠금화면 + 카카오톡 알림 카드 스택 (사이트 헤더 없음, 2026-10-28 사용자 결정). iOS 알림 센터 형태: "위로 쓸어올려서 잠금 해제", 시각 위 날짜 아래, "알림 센터" 제목, 카드 머리줄은 카카오톡 아이콘(`assets/kakaotalk.png`, 사용자 제공) + "카카오톡" + 시각. 기본은 전부 접힘. 모바일 보기 전체 스크롤바 숨김 |

배제한 후보
- 풀블리드 미디어 히어로: 세무 서비스에 대표 사진이 정보를 주지 않는다. 결과물(위임장)이 곧 핵심 시각물이다.
- 검색 우선 히어로: 사용자가 고를 상품이 없다. 할 일은 신고 하나다.

쓰지 않는 부품
- `SectionHead` + 더보기 + 가로 스크롤 카드 레일 (A1 부품). 홈 피드가 없다.
- 하단 탭바. 모바일은 헤더 + 메뉴 시트, 폼 화면만 하단 고정 버튼.
- 서비스 소개 섹션 반복("이렇게 이용하세요" 3단계 카드), 후기 캐러셀, 푸터 링크 농장. 푸터는 사업자 정보 한 줄.

**관리자 셸: C4 아이콘 레일 + 섹션 리스트.** 관리자 IA가 2단계다. 섹션 3개(신고 검토 / 자동 신고 / 운영)
안에 하위 뷰가 각각 큐 필터, 4개 탭, 3개 메뉴로 있다. 섹션 리스트 컬럼에는 그 섹션에서만 의미 있는 것을 둔다:
신고 검토는 큐 잔량, 자동 신고는 실행 에이전트 연결 상태와 긴급 정지 상태, 운영은 지식자료 기준 문서 버전.
monitoring 카테고리에서 C4는 처음이다 (petlive가 C1).

배제한 셸
- C1 다크 레일: 포화 상태이고, 섹션이 3개라 236px 평면 레일이 비어 보인다.
- C2 워크벤치: 하위 뷰 12개를 평면 나열하면 2단계 구조가 사라진다.

관리자에서 쓰지 않는 부품: 전폭 헤더(헤더는 본문 컬럼 위에만), 264px 드로어, 헤더 시계, KPI 카드 4개 나열.

## 적용 규칙

해석: 부가세 대리 신고 접수 웹 for 반기마다 한 번 신고하는 40~50대 개인사업자, 그리고 접수 건과 자동 신고를
하루 종일 처리하는 세무사, 운영자. 다이얼 사용자 V4 / M3 / D4, 관리자 V3 / M2 / D8.

- 사용자 V4: SKILL.md 표의 "웹 예약, 결제" V3에서 하나 올렸다. 위임장 화면은 문서가 가운데를 크게 차지하는
  비대칭 구성이라 정형 그리드(1~3)가 아니다. 그 외 화면은 정형에 가깝다.
- 사용자 M3: 단계 전환, 시트, 서명 패드 피드백까지. 첫 진입 스태거 없음.
- 사용자 D4: 폼은 한 화면 한 과업이지만 증빙과 현황은 정보가 많아 블록 간 24px.
- 관리자 V3 / M2 / D8: "콘솔 목록 (표 중심)" 그대로. 자동 신고 작업은 로그와 대조표가 함께 보여야 한다.

읽은 skill: `mockup-craft` (SKILL.md, anti-slop.md, web.md, console.md). 스타일 skill 없음.
디자인시스템: `design-systems/apple_compact.md` (spec 지정, 2026-10-28 사용자 요청).

(유틸 8 / 카드 / pill 액션), 그림자 하나(제품에만 → 여기서는 위임장 종이에만), 그라데이션 없음, 44px 터치.

## Shape

- radius: 유틸 버튼과 입력 박스 8, 카드와 패널 16, 액션(사용자 웹 주 버튼, 검색, 칩) pill. 관리자 버튼은 DS
  dark-utility처럼 8. 표, 레일, 섹션 구분 면은 0.
- 그림자: 위임장 종이 미리보기에만 `3px 5px 30px rgba(0,0,0,.22)` (DS 유일 그림자). 모달과 드로어는
  스크림 + 1px 헤어라인으로 띄운다.
- 상태 칩: 고정 폭 72px(관리자 표 64px), 높이 24, 가운데 정렬, 라벨 4자 이내.
- 테두리: 1px `--td-line`. 카드 안 카드 금지.

## 사진 매핑

세무 신고 화면은 사진이 정보를 주는 자리가 적다. 핵심 시각물은 위임장 문서, 영수증 증빙, 도장, 서명이고
이것들은 HTML로 실제 문서처럼 만든다 (영수증 썸네일, 도장, 손서명 획). 사진 자리:

| 자리 | 내용 | 출처 |
| --- | --- | --- |
| 담당 세무사 프로필 | 세무사 인물 | 모노그램 (인물 사진 금지 관례) |
| 증빙 업로드 처리 전 원본 | 비스듬히 찍힌 영수증 | HTML 영수증을 기울이고 그늘을 얹어 표현 |

picsum으로 맞출 자리가 생기면 id를 직접 확인한 뒤 이 표에 추가한다.

## 반응형 기준

기준 폭 393 / 768 / 1024 / 1440. 본문 `max-w-[1160px]`, 거터 모바일 24 / 데스크톱 40. 헤더 52px 흰 불투명.

| 화면 | 데스크톱 (lg 이상) | 모바일 |
| --- | --- | --- |
| 신고 신청 | 히어로 2열, 폼은 좌 단계 레일 240 + 우 폼 | 히어로 1열(미리보기 아래로), 한 화면 한 단계, 상단 진행바, 하단 고정 버튼(이전 / 다음) |
| 증빙 제출 | 체크리스트 전폭 (최대 880). AI 안내는 우하단 채팅 버튼으로 여는 우측 드로어 420 (2026-10-28 수정) | 같은 드로어가 전폭으로 열린다. 업로드는 촬영 버튼 우선 |
| 위임장 서명 및 결제 | 좌 위임장 종이, 우 sticky 패널 400 | 위임장 축소 미리보기 → 서명 → 수수료 → 결제수단, 하단 고정 결제 버튼 |
| 내 신고 현황 | 좌 타임라인 + 우 확정 내용, 결제, 서류 | 1열 스택 |
| 알림톡 | 만들지 않음 (`?screen=kakao`는 모바일 보기에서만 열리고, 데스크톱은 내 신고 현황으로 간다) | 잠금화면 전체. 상태바 흰 글자, 배경은 짙은 잠금화면 톤 |

모바일 메뉴는 헤더 우측 버튼 → 전체 화면 시트. 하단 고정 바는 불투명 흰색 + 위 헤어라인.

## 셸 레이아웃 (관리자)

C4. 아이콘 레일 64(그래파이트, 라벨 없음, 활성 섹션만 면 채움) + 섹션 리스트 224(흰 면, 우측 헤어라인) +
본문(풀블리드, 좌우 32). 헤더 52는 본문 컬럼 위에만 얹힌다: 좌측 페이지 위치, 우측 검색, 알림, 계정.
`lg` 미만: 레일은 하단 아이콘 바(그래파이트, 불투명), 섹션 리스트는 본문 위 가로 스크롤 세그먼트. 드로어 없음.
행 상세는 우측 패널 440 (데스크톱 본문 안에 고정 컬럼, `xl` 미만은 오버레이 슬라이드오버).

**2026-10-28 사용자 수정.** 아이콘만 있는 레일은 무엇인지 알 수 없다는 피드백으로, 레일과 섹션 리스트를 합쳐
그래파이트 사이드바 240 하나로 바꿨다: 섹션 제목(아이콘 + 라벨) 아래에 하위 메뉴를 전부 펼치고, 하단에 계정.
사이드바 하단 요약 카드(오늘 처리, 실행 에이전트, 지식자료 기준)는 없앤다. 행 상세 패널은 행을 눌렀을 때만
열린다 (기본 선택 행을 미리 띄우지 않음). 자동화 설정의 모드 카드에는 자동/대기 칩을 붙이지 않는다.

## 표 밀도, 컬럼 예산

- 행 높이 52, 셀 세로 패딩 16 대신 12 + 2줄 셀. 8~12행 + 페이지네이션. 구분선은 행 아래 한 줄.
- 1440에서 본문 폭 1440 - 64 - 224 - 64(좌우 패딩) = 1088. 우측 패널 440이 열리면 표 폭 624.
  - 패널 있는 표(신고 검토, 전체 작업): 기본 `minWidth` 600, 열 5개 이하. 사업자번호, 담당자, 업종은 이름 아래 보조 줄.
  - 패널 없는 표(회원, 결제, 필드 매핑): `minWidth` 960, 열 6개 이하.
- 넘치면 열을 줄이고 값을 보조 줄로 내린다. 좌우 높이가 다른 그리드는 `items-start`.

## Motion

`motion/react`. `prefers-reduced-motion`에서 이동을 끄고 투명도만 남긴다.

- 화면 진입: spring `visualDuration 0.3, bounce 0`, 페이드만. 화면 래퍼에 transform을 주면 모바일 하단 고정 바와
  모달의 `fixed` 기준이 래퍼로 바뀌어 이동은 뺐다. 스태거 없음.
- 신청 폼 단계 전환: 같은 spring, translateX 24 (앞으로 / 뒤로 방향 유지). 공간 연속성.
- 모달과 모바일 시트: spring `visualDuration 0.36, bounce 0.08`, translateY 100% (모바일) / scale 0.98 + 페이드 (데스크톱).
