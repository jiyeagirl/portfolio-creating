# MarketFlow Mobile — Design

## 적용 규칙

- 디자인시스템: `design-systems/claude_compact.md` (spec.md 1행 지정) — 색 토큰, 타입 굵기/트래킹
  위계, radius 문법, "그림자 최소화·표면색 대비로 위계 표현" 철학의 1차 소스. claude_compact의
  타이포 원본(Copernicus/StyreneB)은 CLAUDE.md 규칙상 항상 Pretendard로 대체하되, size/weight/
  line-height/letter-spacing 값은 그대로 재현했다.
- CLAUDE.md 규칙이 항상 우선하는 항목: Pretendard 타이포그래피, iPhone 16 Pro 단일 기기 프레임
  (흰 배경), 8px 스페이싱 그리드. claude_compact의 `spacing` 토큰은 8px 배수(4/8/12/16/24/32/48)로
  이미 맞아떨어져 그대로 채택했다.
- `스타일: high-end-visual-design`이 spec.md에 지정되어 있으나 이 워크스페이스(`.claude/skills/`)에
  설치되어 있지 않아 CLAUDE.md의 "Skill Usage Policy"(미설치 시 조용히 건너뛰고 이 문서의 UI
  Generation Rules로 대체) 정책에 따라 건너뛰었다.
- `design-taste-frontend`(v2, `DESIGN_VARIANCE`/`MOTION_INTENSITY`/`VISUAL_DENSITY` 다이얼과
  em-dash 금지 섹션 확인됨)를 기본기로 로드했다. 이 스킬은 랜딩페이지/포트폴리오 전제(문서
  13절 "Out of scope: 대시보드/멀티스텝 폼")라 본 프로젝트(승인 인박스형 모바일 툴)에는
  구조적 패턴(히어로, 벤토, 마퀴 등)을 적용하지 않고, 색 캘리브레이션(액센트 1개, 채도 절제),
  이미지 진위성 규칙, 폼 라벨 배치(라벨은 인풋 위), 대비 체크, em-dash 금지, "Jane Doe"/가짜
  브랜드명 금지 같은 범용 품질 규칙만 가져왔다.
- 다이얼: `DESIGN_VARIANCE: 4` (승인함→미리보기→처리로 이어지는 단계형 검토 플로우가 핵심이라
  예측 가능한 리스트/카드 구조를 우선했다) · `MOTION_INTENSITY: 3` (화면 전환은 워크스페이스
  표준 스프링만 사용, 장식적 모션 없음) · `VISUAL_DENSITY: 5` (승인 대기 리스트·필터·검수 코멘트가
  있는 업무 도구라 포트폴리오 랜딩보다 밀도를 높였다).
- `projects/monitoring/marketflow`(웹 콘솔, 병행 작업 중)와 색 토큰·컴포넌트를 공유하지 않는다.
  이 문서의 팔레트는 `.marketflow-mobile` 스코프의 `--mfm-*` CSS 변수로, 웹 콘솔이 무엇을 쓰든
  충돌하지 않는다. 워드마크는 본 프로젝트 `spec.md` 1행이 지정한 "MarketFlow"를 그대로 썼다
  (웹 콘솔 쪽 spec.md는 표시 제품명을 "ContentPilot"으로 별도 명명했으나, 빌드 시점에 그쪽
  design.md가 아직 확정되지 않아 동기화할 수 없었다 — 두 프로젝트 모두 폴더/코드베이스 상
  "marketflow" 계열이라는 점은 유지된다).

액센트는 코랄(`--mfm-primary`) 한 가지만 UI 크롬(주요 버튼, 탭 활성, 배지 카운트, 승인 대기
콜아웃의 CTA 원형 버튼)에 쓴다. 상태 배지(대기/수정요청/반려/완료)는 별도 시맨틱 토큰을 쓰고
코랄과 섞지 않는다. "채널별 발행 예정" 카운트 등 정보성 숫자는 잉크/뮤트 중립 톤만 쓴다.

**리듬 (수정됨)**: 최초 빌드에서는 claude_compact의 "크림↔다크 표면을 밴드마다 번갈아 배치"
원칙을 상단 `ScreenHeader`와 하단 탭바에도 `--mfm-surface-dark`로 적용해 "다크 크롬 + 크림
콘텐츠" 정체성을 시도했으나, 폰 프레임 안에서 상단/하단이 화면마다 항상 보이는 고정 크롬이라
실제로는 검게 눌린 인상이 강해 피드백에 따라 되돌렸다. claude_compact의 밴드 교대 원칙은
스크롤에 따라 지나가는 섹션에는 맞지만, 항상 떠 있는 고정 크롬에는 과했다. 현재는 상단
`ScreenHeader`와 하단 탭바 모두 `--mfm-surface`(크림에 가까운 흰색) + `--mfm-hairline` 보더로
통일하고, 탭 활성 상태만 `--mfm-primary`(코랄)로 표시해 브랜드 액센트를 준다. 다크 표면은 홈
화면의 "오늘의 승인 대기" 콜아웃 한 곳에만 남겨(`product-mockup-card-dark` 문법) 콘텐츠
영역 안에서 핵심 수치에 시선을 모으는 단발성 강조로 한정했다.

## Shape

- radius 위계(claude_compact 문법): `md`=8px — 버튼/인풋/필터칩 배경 미사용, `lg`=12px — 카드
  전체(리스트 아이템, 정보 카드, StatTile), `pill`=9999px — 배지·필터칩·탭·토글.
  카드에 pill을 쓰거나 버튼에 12px 초과를 쓰지 않는다(문법 혼용 금지).
- 시트 상단 모서리만 예외로 20px(`rounded-t-[20px]`) — 필터 바텀시트가 화면 하단에서 올라오는
  모달임을 카드와 구분해서 알려주는 유일한 확대 radius.
- 그림자: claude_compact "그림자 최소화, 표면색 대비로 위계" 원칙을 그대로 따라 카드 그림자를
  쓰지 않는다. 카드 구분은 `1px solid var(--mfm-hairline)`. 유일한 예외는 하단 고정 액션 바
  위쪽 1px 보더(엣지 정합성 규칙과 충돌하지 않는 불투명 보더)와 다크 승인 대기 콜아웃(그림자
  대신 표면색 자체의 명도 대비로 떠 보이게 한다).
- 버튼 active 상태: `active:scale-[0.98]` 공통 적용.

## 기기 프레임 안쪽 규칙

- 상단 `ScreenHeader`(다크 크롬, `--mfm-surface-dark` 고정값)와 하단 `BottomNav`,
  콘텐츠 검수 화면의 하단 고정 액션 바(`--mfm-surface` 고정값) 모두 **완전 불투명** 표면만
  쓰고 `backdrop-blur`/`backdrop-filter`를 전혀 쓰지 않는다 — Chromium에서 backdrop-filter가
  `PhoneFrame`의 `rounded-[50px]` 클립을 뚫고 나가 하단 모서리에 흰 틈이 새는 반복 버그를
  원천 차단한다.
- 승인함 화면의 필터 바텀시트 스크림은 `bg-black/45` 단색 반투명(필터 없음)이라 동일한 문제가
  없다. 시트 자체도 `--mfm-surface` 불투명 배경.
- 모든 edge-anchored 요소는 화면 박스 내부에 `absolute`로만 배치했고 `fixed`나 음수 오프셋을
  쓰지 않았다.
- 빌드 완료 후 홈/승인함/알림/마이페이지/콘텐츠 검수 5화면 모두 하단 모서리를 확인해 검은
  섀시 밖으로 흰 틈이 새지 않음을 확인했다.

## Motion

- 이 앱은 탭 전환형 구조(화면 간 슬라이드 트랜지션이 아니라 `useState`로 즉시 스위칭)라
  화면 전환 자체에 애니메이션 라이브러리를 걸지 않았다 — `MOTION_INTENSITY: 3` 판단에 따른
  의도적 절제. 대신 인터랙션 피드백만 워크스페이스 표준을 따른다.
- 버튼/카드 탭 피드백: `active:scale-[0.98]`로 통일.
- 토글(`Toggle`)과 필터칩은 `transition-colors duration-200`.
- 바텀시트는 즉시 표시/제거(JS 애니메이션 없음) — 워크스페이스 표준 스프링(stiffness 300,
  damping 30)을 쓰는 대신, 목업 범위에서 motion 의존성을 늘리지 않는 쪽을 택했다. 추후
  스크린샷 이상의 인터랙션 데모가 필요해지면 `motion/react`의 `AnimatePresence` +
  `y: 40→0` 슬라이드를 추가할 수 있는 구조로 컴포넌트를 분리해 두었다(필터 시트, 완료 화면).
- `prefers-reduced-motion`은 워크스페이스 전역 CSS 규칙을 그대로 상속한다. 이 프로젝트가
  추가한 커스텀 애니메이션이 없어 별도 처리가 필요 없다.
