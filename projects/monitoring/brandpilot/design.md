# BrandPilot - Design Notes

## 적용 규칙

- `디자인시스템: vercel_compact` (spec.md 지정) - 색/반경/간격/그림자 철학의 **최우선 출처**.
- `스타일: minimalist-ui` (spec.md 지정) - 두 개가 함께 지정됐으므로 역할을 나눴다.
  **색상 값은 vercel_compact**(우선순위 상위), **처리 방식은 minimalist-ui**가 맡는다:
  플랫한 표면, 1px 헤어라인만으로 구획, 색을 희소 자원으로 취급, 그라데이션/무거운 그림자
  금지, 마이크로 라벨은 대문자 + 넓은 자간, 카드 내부 여백을 넉넉히.
- 충돌은 워크스페이스 `CLAUDE.md`가 먼저 이긴다:
  - minimalist-ui가 SF Pro / Geist / Switzer를 지정하지만 **Pretendard 고정**을 따른다.
  - minimalist-ui의 에디토리얼 세리프(Lyon/Newsreader)는 쓰지 않는다. 히어로가 없는 고밀도
    콘솔이라 적용 지점 자체가 없고, vercel_compact의 "굵기 천장 600 + 음수 자간" 규칙과
    충돌한다.
  - minimalist-ui의 웜 본(`#F7F6F3`) 캔버스 대신 vercel_compact의 중성 캔버스를 쓴다
    (우선순위 상위 문서의 색을 따른다).
  - minimalist-ui의 `rounded-full` 금지(큰 컨테이너/기본 버튼)와 vercel_compact의 pill CTA가
    충돌 - 콘솔이므로 vercel_compact의 **네비 스케일(6px)** 을 버튼에 쓰고 pill은 배지에만
    남겨 양쪽을 모두 만족시킨다.
- `design-taste-frontend`(v2)는 §13에서 **"대시보드 / 고밀도 제품 UI / 관리자 패널은
  OUT OF SCOPE"** 라고 명시하므로 랜딩페이지형 규칙(히어로 구성, 스크롤 리빌, 마퀴)은
  적용하지 않는다. 대신 범용 규칙만 가져온다: 액센트 1개 고정, 반경 체계 1개 고정,
  **em dash 전면 금지**(§9.G), 버튼/폼 대비 WCAG AA, 페이지 테마 락(라이트 단일),
  "Jane Doe"류 가짜 데이터 금지. 화면 구조는 `CLAUDE.md`의 "Enterprise UI" 절을 따른다.
- `DESIGN_VARIANCE 3 / MOTION_INTENSITY 3 / VISUAL_DENSITY 7` - 승인/게시/성과를 다루는
  운영 콘솔이라 레이아웃은 예측 가능한 그리드, 모션은 상태 전환 피드백에만, 밀도는
  높게(표는 촘촘, 카드 여백은 확보).
- `_reference-*`(assetflow)는 **구조만** 재사용했다: 반경 3단계, 미세 그림자 스택,
  `word-break: keep-all`, 모노 유틸(tabular-nums), 진입 트랜지션 420ms
  `cubic-bezier(.16,1,.3,1)`, `prefers-reduced-motion` 블록, 배지 5단계 톤 **구조**,
  `Table`의 `minWidth` prop 패턴. 색과 톤 어휘는 전부 새로 정의했다.

## Tokens / 팔레트 (`styles/brandpilot.css`, `.brandpilot` 스코프)

액센트는 vercel_compact 팔레트 안에 이미 있는 **바이올렛 `#7928ca`** 를 쓴다. 새 색을
발명하지 않으면서도 같은 문서를 쓰는 assetflow(링크 블루 `#0070f3`)와 정체성이 갈린다.
뷰티 브랜드의 AI 크리에이티브 도구라는 도메인에도 블루보다 맞는다.

| 역할 | 토큰 | 값 | 용도 |
| --- | --- | --- | --- |
| 캔버스 | `--bp-canvas` | `#ffffff` | 페이지 바닥, 카드 |
| 캔버스(연) | `--bp-soft` | `#fafafa` | 사이드바, 보조 블록 |
| 캔버스(연2) | `--bp-soft-2` | `#f5f5f5` | 활성 내비, 중립 배지 바탕 |
| 잉크 | `--bp-ink` | `#171717` | 헤딩, 주요 텍스트 |
| 본문 | `--bp-body` | `#4d4d4d` | 본문, 라벨 |
| 보조 | `--bp-mute` | `#888888` | 캡션, 플레이스홀더 |
| 헤어라인 | `--bp-hairline` | `#ebebeb` | 1px 구획선 (강조: `--bp-hairline-strong` `#a1a1a1`) |
| 액센트 | `--bp-accent` | `#7928ca` | 기본 CTA, 활성 상태, 포커스, AI 관련 표식 |
| 액센트(연) | `--bp-accent-soft` | `#f4e9fd` | 액센트 배지 바탕, 선택 행 |
| 액센트(짙) | `--bp-accent-deep` | `#5f1f9e` | hover, 액센트 위 텍스트 |
| 액센트 전경 | `--bp-on-accent` | `#ffffff` | 액센트 배경 위 글자 |

액센트 사용 규칙: 화면당 **채운 액센트 면은 1개까지**(주요 CTA 또는 강조 지표 타일 하나).
나머지 액센트는 텍스트/아이콘/1px 테두리로만 쓴다. AI가 생성했거나 AI가 제안한 것에는
액센트를 붙이고, 사람이 만든 것에는 붙이지 않는다 - 액센트가 "AI 산출물" 신호를 겸한다.

상태 배지는 5단계로 고정한다(장식이 아니라 승인/게시 상태의 기능색):

| 톤 | 전경 / 바탕 | 쓰이는 상태 |
| --- | --- | --- |
| `neutral` | `#4d4d4d` / `#f5f5f5` | 초안, 보관, 종료 |
| `accent` | `#5f1f9e` / `#f4e9fd` | AI 생성됨, 생성 중, 진행중 캠페인 |
| `warn` | `#ab570a` / `#ffefcf` | 승인 대기, 예약됨, 수정 요청 |
| `success` | `#346538` / `#edf3ec` | 승인 완료, 게시 완료 |
| `danger` | `#c50000` / `#f7d4d6` | 반려, 게시 실패, 가이드 위반 |

`success`의 그린만 vercel_compact에 없다(그 문서는 success를 링크 블루로 둬서 승인/게시
완료를 파랑으로 칠하게 되고, 액센트 바이올렛과 나란히 놓이면 두 번째 액센트처럼 읽힌다).
그래서 이 한 톤만 minimalist-ui의 Pale Green(`#EDF3EC` / 텍스트 `#346538`)에서 가져왔다 -
두 지정 소스 안에서 해결했고 새 색을 발명하지 않았다.

차트는 액센트 단일 색조의 명도 단계만 쓴다: `--bp-chart-1` `#5f1f9e` → `--bp-chart-5`
`#ede0fa`, 그 외 계열은 `--bp-chart-rest` `#ebebeb`. 이중 축을 쓰지 않는다.

채널 식별색은 두지 않는다. 인스타그램/틱톡/유튜브를 각 브랜드 색으로 칠하면 액센트 1개
규칙이 깨지므로 **채널은 아이콘과 텍스트로만** 구분한다.

## Shape

- 반경: 버튼/입력/작은 배지 컨테이너 `6px`, 카드/패널/드로어 `8px`, 완전한 pill(배지,
  아바타, 토글)만 `9999px`. 세 단계 외에는 쓰지 않는다(minimalist-ui의 "crisp 8/12px 최대"와
  vercel_compact의 `sm 6 / md 8`이 겹치는 구간).
- 그림자: 단일 두꺼운 drop-shadow 금지(두 소스가 모두 금지). `--bp-shadow`(미세 3단 스택)와
  `--bp-shadow-pop`(드로어/팝오버)만 쓴다. 카드 대부분은 그림자 없이 1px 헤어라인만으로
  분리한다 - minimalist-ui의 플랫 원칙.
- 폰트 굵기 천장 600. 700/800은 쓰지 않는다(vercel_compact 명시 규칙).

## Typography

Pretendard 고정(`app/globals.css`에 이미 등록). vercel_compact의 스케일을 콘솔 밀도에 맞게
축소해 쓴다:

| Role | Size / Line | Weight | 용도 |
| --- | --- | --- | --- |
| Page Title | 24 / 32 | 600 | PageHead 타이틀, 자간 -0.96px |
| Section Title | 15 / 22 | 600 | CardHead, 패널 제목 |
| Body | 14 / 20 | 400 | 본문, 설명, 자간 -0.28px |
| Label | 13 / 20 | 500 | 폼 라벨, 배지, 테이블 헤더 |
| Caption | 12 / 16 | 500 | 보조 정보, 타임스탬프 |
| Eyebrow | 11 / 16 | 500 | 대문자 + 자간 0.08em, 모노로 렌더 |

- `.bp-mono`(Geist Mono, `tabular-nums`)는 수치/일시/해시태그/조회수처럼 자릿수를 맞춰 읽는
  값에만 쓴다. 본문에는 절대 쓰지 않는다(vercel_compact 명시 규칙).
- `word-break: keep-all; overflow-wrap: break-word;`를 루트에 걸어 한글 어절 중간 줄바꿈을
  막는다. `anywhere`는 `keep-all`을 무력화하므로 쓰지 않는다.
- **em dash 사용 금지.** 화면 카피 전체에서 일반 하이픈만 쓴다
  (`design-taste-frontend` §9.G).

## 차트 기하

차트는 라이브러리 없이 직접 그린다. 원이 찌그러지거나 경계가 계단처럼 깨지는 사고가
반복되는 지점이라 규칙을 못박아 둔다.

- **`DonutChart`** - viewBox 단위를 px와 1:1(`0 0 168 168`)로 두고, 세그먼트는
  `stroke-dasharray`가 아니라 **호(`<path>` + `A` 커맨드)** 로 그린다. 회전은 CSS
  `transform`이 아니라 좌표 계산(-90도)에 넣는다. 이유는 셋 다 실제로 깨졌기 때문이다.
  작은 viewBox(`0 0 36 36`)를 168px로 확대하면 세그먼트 경계가 어긋나 지그재그로 보이고,
  SVG에 CSS 회전을 걸면 크로미움이 레이어를 래스터화한 뒤 돌려서 같은 증상이 나오며,
  바깥 반지름(`R + 선폭/2`)이 viewBox를 넘으면 SVG 루트의 기본 `overflow: hidden`에 잘려
  상하좌우 네 지점이 평평해진다. 그래서 **`R + STROKE/2 < SIZE/2`를 반드시 지킨다**
  (현재 72 + 11 = 83 < 84).
- **`LineChart`** - 면과 선만 SVG(`preserveAspectRatio="none"`)로 그리고, 꼭짓점은 고정
  px 크기의 HTML 원으로 SVG 바깥에 얹는다. `none`은 viewBox를 가로세로 따로 늘리므로 그
  안의 `<circle>`은 반드시 타원이 된다.

## 셸 레이아웃

`_reference-app-shell.tsx`의 T자형(헤더가 사이드바 위)을 따른다. 운영자 전용 콘솔이 아니라
마케팅팀이 상시 쓰는 업무 도구라 다크 레일(F자형)은 쓰지 않는다.

| 항목 | 값 |
| --- | --- |
| 헤더 | 높이 64px, `sticky top-0 z-30`, `border-b` 헤어라인, 캔버스 배경 |
| 사이드바 | 폭 236px, `sticky top-16`, `h-[calc(100dvh-64px)]`, `--bp-soft` 배경, `lg:` 이상에서만 |
| 모바일 드로어 | `fixed inset-0 z-50 lg:hidden`, 패널 264px, 스크림 `rgba(0,0,0,0.32)` |
| 본문 | `px-4 py-6` → `lg:px-8 lg:py-8`, `mx-auto max-w-[1400px]` |
| 내비 항목 | 아이콘 15px(active 시 `weight` bold에서 fill로), `rounded-[6px] px-3 py-2`, 13.5px |
| 내비 그룹 | 4개(현황/콘텐츠/운영/브랜드), 그룹 라벨은 모노 11px 대문자 자간 0.08em |

사이드바를 `--bp-soft`로 한 단계만 낮춰 콘텐츠 영역(순백)과 분리한다. 다크 반전을 쓰지
않는 이유는 minimalist-ui가 큰 면적의 강한 색면을 금지하기 때문이다.

## 표 밀도 · 컬럼 예산

`Table`은 `overflow-x-auto` 안에 있어 컬럼 폭 합이 컨테이너를 넘으면 **마지막 열이 조용히
잘린다.** 1440px에서 사이드바(236) + 본문 좌우 패딩(64) + 카드 패딩(40)을 빼면 실제 컬럼
폭이 약 1100px, 2열 그리드 안에 놓이면 약 520px이다. 그래서 기본 `minWidth`는 `560`으로
잡았다.

- 열은 **6개를 넘기지 않는다.** 넘으면 값을 보조 줄(셀 안 두 번째 줄)로 내리고 열을 줄인다.
- 썸네일과 제목은 한 셀에 합친다. 썸네일만 독립 열로 두면 열 예산을 낭비한다.
- 좌우 높이가 다른 그리드에는 `items-start`를 준다. 없으면 짧은 쪽 카드가 늘어난다.
- 상태/채널처럼 폭이 고정된 열에는 `nowrap`을 준다.

## Motion

- `MOTION_INTENSITY 3`. 화면 전환은 `opacity + y:6에서 0`, spring(stiffness 300, damping 30).
  카드/행 진입은 `.bp-enter`(420ms `cubic-bezier(.16,1,.3,1)`) 한 겹만.
- 인터랙션 피드백은 `transform`과 `opacity`만 애니메이션한다(`active:scale-[0.99]`).
  레이아웃을 흔드는 속성은 쓰지 않는다.
- 무한 루프 모션은 **AI 생성 진행 표시(`.bp-pulse`) 하나뿐**이고, 실제로 생성 중일 때만
  나타난다. 정보성 카드는 움직이지 않는다.
- `prefers-reduced-motion: reduce`에서 진입 애니메이션과 pulse를 모두 끈다.

  오늘 이후에 끝나야 하므로 종료일만 5월까지 걸친다.
- 콘텐츠 생성/발행 이력: 2026-03-05 ~ 2026-04-22
- 예약 게시: 2026-04-24 ~ 2026-04-29
- 성과 추이 차트: **1월~4월 4개월**(`monthlyReach`, `monthlyEngagement`). 기간이 4개월이라
  6개월 차트를 쓰지 않는다. 화면 문구도 "최근 6개월"이 아니라 "1월부터 4월까지"로 쓴다.
- 게시 캘린더: **2026년 4월**. 4월 1일이 수요일이라 앞 3칸이 비고 30일까지다
  (`publishing-screen.tsx`의 `APR_LEAD` / `APR_DAYS`).

**계절 어휘도 이 기간에 묶인다.** 1월에 "여름 자외선 캠페인"이 진행 중인 것처럼 읽히면
목업의 사실성이 깨지므로, 진행중 캠페인은 겨울 끝에서 봄(겨울 보습 / 환절기 진정 / 봄 수분)
으로 잡고 여름 소재(선케어)는 **4월 말 시작하는 "사전 예열" 캠페인에만** 쓴다. 사진 매핑도
같은 원칙을 따른다 - 여름감이 강한 id 64, 646은 예열 캠페인 콘텐츠와 로그인 패널에만 쓰고,
봄에 해당하는 id 106, 152, 375를 진행중 캠페인에 배치했다.

날짜를 바꿀 때는 `lib/mock-data.ts`의 위 범위와 함께 `publishing-screen.tsx`의 달력 상수,
`dashboard-screen.tsx`의 기준일 문구, `analytics-screen.tsx`의 기간 표기를 같이 맞춘다.

## 레퍼런스 탐색의 수집 범위

"경쟁사 모니터링"은 쓰지 않는다. 특정 브랜드 계정을 지목해 게시물을 자동 수집하는 기능은
플랫폼 약관과 저작권 측면에서 위험이 있어, 목업이라도 그 형태로 그리지 않는다. 대신
**각 플랫폼이 공개한 API로 업계 광고를 수집하고 소구 방식으로 분류해 레퍼런스
데이터베이스를 만드는** 기능으로 정의한다. 화면에 걸리는 제약은 셋이다.

1. **수집 소스는 실재하는 공개 API로만 적는다.** "광고제 수상작 아카이브" 같은 막연한
   출처는 쓰지 않는다 - 어떻게 가져오는지 설명이 안 되면 목업이 붕 뜬다. `RefSource`가
   `platform` + `endpoint` + `note`(권한·할당량 제약)를 강제하고, 화면에도 엔드포인트를
   그대로 노출한다.

   | 소스 | 엔드포인트 | 상태 | 비고 |
   | --- | --- | --- | --- |
   | Meta 광고 라이브러리 | `Ad Library API · GET /ads_archive` | 연동됨 | 앱 검수·신원 확인 필요. EU 집행 건은 전체 카테고리, 그 외 지역은 정치·사회 이슈 광고만 공개 |
   | Instagram 해시태그 공개 게시물 | `Graph API · /ig_hashtag_search → /recent_media` | 연동됨 | 비즈니스 계정 토큰. 해시태그 7일 30개 제한, 비공개 계정 제외 |
   | YouTube 공개 동영상 | `Data API v3 · search.list` | 연동됨 | 일 10,000 유닛, 검색 1회 100 유닛 |
   | 네이버 블로그 공개 포스트 | `검색 API · /v1/search/blog.json` | 연동됨 | 일 25,000회. 본문 미저장 |
   | TikTok Creative Center | 조회 API 없음 | 수동 등록 | 공개 페이지지만 API가 없어 담당자가 URL 등록 |
   | TikTok Commercial Content Library | `Research API · /commercial_content/ad/query` | 검수 대기 | 연구 목적 접근 승인 필요 |

   **`state`가 셋인 이유**: 전부 "연동됨"으로 두면 거짓말이 된다. 조회 API가 없는
   Creative Center는 `manual`, 승인 대기 중인 Commercial Content Library는 `review`로
   두고 수집량 0으로 표시한다. 이 세 상태가 있어야 "공개돼 있다고 전부 API로 긁을 수 있는
   건 아니다"라는 현실이 화면에 드러난다.

   소스 연동 드로어의 hint에도 "로그인 세션이나 비공개 데이터를 요구하는 주소는 거부된다"를
   명시한다. 새 소스를 추가할 때는 **실제로 존재하는 공개 엔드포인트인지 먼저 확인한다.**
2. **개별 브랜드에 귀속시키지 않는다.** `Reference`에 브랜드 필드가 없다. 분류는
   `refCategories`(수분 소구 / 성분 소구 / 숏폼 루틴 / 시즌 캠페인 / 무드 브랜딩)로만
   하고, 카드·표·드로어 어디에도 "어느 브랜드 광고인지"를 적지 않는다.
3. **AI 산출물도 브랜드가 아니라 패턴을 말한다.** `referenceSummary`와
   `aiKeywordInsights`는 "A사가 무엇을 했다"가 아니라 "수집분 118건 중 41건이 수치를 먼저
   노출했다" 형태의 집계 문장만 쓴다.

브랜드 가이드의 `경쟁사 직접 비교 금지` 규칙은 그대로 둔다. 이건 수집이 아니라 카피에서
타사를 언급하지 못하게 막는 검사라 방향이 같다.

## 익명화

회사명은 워크스페이스 관례대로 알파벳 기반으로 쓴다 - 운영 주체는 `A뷰티`. 담당자 이름,
제품 라인명, 해시태그, 수치는 사실적이되 가상이다. 인스타그램/틱톡/유튜브는 실제 플랫폼 이름이므로 그대로 쓴다
(특정 기업을 사칭하는 것이 아니라 채널 종류를 가리킨다).
