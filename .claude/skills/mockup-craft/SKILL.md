# mockup-craft

이 워크스페이스의 목업이 "AI가 만든 것 같다"는 말을 듣지 않게 하는 디자인 판단 모음이다.
설치된 외부 skill 6종(supanova-design-engine, design-taste-frontend, supanova-premium-aesthetic,
redesign-existing-projects, high-end-visual-design, minimalist-ui)에서 **앱 화면과 콘솔에 맞는 것만**
추리고, 사용자가 반복해서 직접 고친 사항을 합쳤다. 외부 skill들은 랜딩 페이지용이라 그대로 따르면
오히려 AI 티가 난다 (예: 영어 대문자 아이브로우 필을 의무화한다).

## 읽는 순서

1. 이 파일 전체
2. `references/anti-slop.md`: AI 티 목록. 빌더와 리뷰어가 같은 원본을 쓴다.
3. 플랫폼 문서. `_reference.md`의 `- 프리셋:` 줄을 따른다:
   - `app` 모바일 앱 → `references/app.md`
   - `web` 고객용 반응형 웹 → `references/web.md`
   - `console` 웹 콘솔 → `references/console.md`
   - `--with-admin`이면 관리자 화면용으로 `console.md`도 읽는다.

`.claude/hooks/pre-write-skill-gate.mjs`는 필요한 문서를 읽기 전에 새 화면 파일을 쓰지 못하게 막는다
(`components/admin/` 아래 파일은 console.md 기준).

**출처 표시.** 수치와 새로 만든 규칙 뒤에 붙인다.
- (사용자): 사용자가 직접 고친 이력
- (CLAUDE.md): 워크스페이스 규칙
- (SDE) supanova-design-engine, (DTF) design-taste-frontend, (RDP) redesign-existing-projects,
  (MIN) minimalist-ui, (HEV) high-end-visual-design, (SPA) supanova-premium-aesthetic
- **(임의)**: 외부 근거 없이 정한 시작값이다. 결과를 보고 조정하고, 조정하면 표시를 (사용자)로 바꾼다.

## 우선순위

1. `CLAUDE.md` UI Generation Rules가 이긴다. Pretendard, 기기 프레임, 8px 그리드, 금지 문자
   (em dash, 중간점), 사진 규칙, 팔레트 구성 1~6, 스케일 복제 금지. 여기서 다시 쓰지 않는다.
2. `spec.md`가 `디자인시스템:`을 지정하면 그 문서의 토큰과 컴포넌트 스펙
3. `spec.md`의 `스타일:` skill. 방향만 가져온다. 아이브로우 필, 이중 베젤 카드 의무화, `py-32`
   섹션 여백 같은 랜딩 규칙은 따르지 않는다.
4. 이 skill

## 1. 시작할 때 한 줄로 해석한다 (DTF)

design.md "적용 규칙" 절 맨 위에 적는다.

```
해석: <화면 종류> for <누가, 어떤 상황에서>. 다이얼 V<n> / M<n> / D<n>.
예) 해석: 필름 카메라 촬영 앱 for 야외에서 한 손으로 찍는 20대. 다이얼 V5 / M5 / D3.
예) 해석: 중고 IT 자산 매각 콘솔 for 매일 입찰을 확인하는 총무 담당자. 다이얼 V3 / M2 / D7.
```

## 3. 화면 골격은 화면마다 다르게

AI 티의 가장 큰 원인은 색이 아니라 **모든 화면이 같은 골격**이라는 것이다 (CLAUDE.md, ARCHETYPES.md).

- 홈 아키타입은 `ARCHETYPES.md`에서 배정한다. 스스로 배정할 때 A1은 금지, spec이 `아키타입:`을 적었으면 그대로 따른다 (CLAUDE.md).
- 홈 외 화면은 아래 어휘에서 고르고, **인접한 두 화면이 같은 골격이면 안 된다.**
  이 어휘와 규칙은 (임의)다. DTF와 SDE의 "인접 섹션 레이아웃 반복 금지"를 화면 단위로 넓혔다.
  - list-first: 필터나 탭 + 그룹핑된 리스트
  - detail-hero: 대표 미디어 + 핵심 정보 + 하단 고정 CTA
  - form-flow: 단계 표시 + 한 화면 한 질문
  - map/media-led: 지도나 미디어가 화면 대부분, 정보는 시트로
  - summary+table: 한 줄 지표 + 표 (콘솔)
  - master-detail: 목록 + 슬라이드오버나 우측 패널 (콘솔)
- 한 화면 안에서도 인접한 블록은 처리 방식을 바꾼다. "흰 카드 N개"를 쌓지 않는다 (SDE, DTF).
- 카드는 elevation이 의미를 가질 때만 쓴다 (눌러서 들어가는 단위, 떠 있는 시트). 나머지는 여백,
  `divide-y`, 배경 톤 차이로 묶는다 (SDE, DTF).

## 4. 타이포와 숫자

- 굵기는 400, 500, 600, 700을 모두 쓴다. 크기만으로 위계를 만들지 않는다 (RDP, SDE).
  700 이상은 화면 제목과 핵심 숫자 하나 정도로 제한한다 (임의).
- 한글 제목은 `leading-snug`로 한다. `leading-none`은 금지다 (SDE).
  - 자간은 약 -0.02em까지 (임의).
  - 한글 라벨과 캡션에는 양의 자간(`tracking-wide`, `tracking-[0.1em]`)을 주지 않는다
    (임의. RDP의 "작은 대문자에는 양의 자간"을 한글에 맞게 뒤집었다).
- 전역 `word-break: keep-all` (SDE). 긴 문단은 `text-wrap: pretty`, 짧은 제목은 `balance` (RDP).
- **숫자:**
  - 큰 숫자 옆에 단위를 붙이지 않는다. `1,234건`, `5,806만원` 금지. 단위는 라벨로 옮긴다:
    `정산 대상 건수 (건)`, `예상 매각 금액 (만원)`. 숫자는 600 안팎, 자간은 기본에 가깝게 (사용자).
  - 행마다 단위가 다른 표(EA와 kg 혼재)만 값 옆 단위를 허용한다 (사용자).
  - 표의 숫자 열은 `tabular-nums`에 오른쪽 정렬, 헤더에 단위를 쓴다: `금액 (원)` (RDP).
  - 둥근 수를 피한다: `47,200`, `4.87`, `98.7%` (SDE). 대신 합계와 건수는 서로 맞아야 한다 (DTF).

## 5. 정렬과 넘침

스크린샷에서 가장 먼저 "깨져 보이는" 문제다.

- 좌측 정렬 기준선은 화면 전체에서 하나다 (예: 모바일 24px). 제목, 카드 내용, 리스트가 서로 다른
  x에서 시작하면 안 된다 (임의. filmate 리뷰의 정렬선 어긋남 지적에서 나왔다).
- 나란한 카드들의 제목, 설명, 가격, 버튼은 같은 높이에 온다. 카드는 `flex flex-col`, 하단 요소는
  `mt-auto` (RDP).
- 아이콘과 텍스트는 세로 중심을 맞춘다. 수학적 중앙이 어색하면 1~2px 광학 보정을 한다 (RDP).
- 넘침 방지 (사용자. filmate 설정 화면에서 토글 노브가 카드 밖으로 튀어나온 사례):
  - 텍스트를 담은 flex 자식: `min-w-0` + `truncate` 또는 `line-clamp-2`
  - 숫자, 금액, 날짜: `whitespace-nowrap`
  - 배지, 토글, 아이콘 버튼, 화살표: `shrink-0`
  - 토글은 `components/shared/toggle.tsx`를 쓰고, 트랙 폭 안에서 노브가 움직이는지 본다.
- 목업 데이터에서 **가장 긴 실제 문자열**로 한 번 확인한다 (긴 상품명, 긴 회사명, 7자리 금액) (임의).

## 6. 모션

- **왜 움직이는지 한 문장으로 말하지 못하면 뺀다.** 유효한 이유는 위계 안내, 피드백, 상태 전환,
  공간 연속성뿐이다 (DTF).
- `transform`과 `opacity`만 움직인다 (SDE). `prefers-reduced-motion`을 지원한다 (CLAUDE.md).
- 스크롤에 반응하는 효과는 `IntersectionObserver`로 한다. `window.addEventListener('scroll')`은
  쓰지 않는다 (SDE, DTF).
- 타이밍은 아래에서 고르고, 직전 프로젝트와 다른 조합을 쓴다 (CLAUDE.md 스케일 복제 금지).
  `cubic-bezier(.16,1,.3,1)`은 이미 여러 프로젝트에 번진 값이라 선택지에 없다 (CLAUDE.md).
  아래 표의 **ms와 px 값은 전부 (임의)**다.

  | 용도 | 선택지 |
  | --- | --- |
  | 화면 진입 (화면 전환) | 앱, 웹 200~320ms standard 또는 spring. 콘솔 180~280ms |
  | 눌림, hover | 120~200ms, ease-out 또는 거의 선형 |
  | 시트, 패널, 드로어 | 앱, 웹 240~360ms standard easing 또는 spring (드래그가 있으면 spring). 콘솔 180~280ms |
  | 첫 진입 스태거 | 화면당 1회, 6개 이하, 이동 12 또는 16px (8px는 이미 번진 값), 간격 30~60ms |
  | 진행, 로딩 막대 | 선형 |

- 눌림 피드백은 프로젝트마다 하나로 고정하고, 직전 프로젝트와 다르게 고른다 (CLAUDE.md):
  `scale(0.97~0.98)` / `translateY(1px)` / 배경 톤 / 없음 (0.98은 SDE, 나머지 선택지는 임의).
  이 목록이 워크스페이스의 유일한 선택지다. CLAUDE.md `## Motion`도 여기를 가리킨다.
- 무한 반복 애니메이션, 떠다니는 장식, 스크롤마다 나타나는 효과는 쓰지 않는다 (DTF. SDE의 float는 뒤집었다).
- 콘솔 표의 행을 하나씩 등장시키지 않는다 (임의).

## 7. 끝내기 전 점검표

빌더는 시각 검증 루프(`npm run visual`) 전에 스스로 확인하고, 리뷰어는 스크린샷을 이 표와
`references/anti-slop.md`로 판정한다.

1. design.md에 해석 한 줄과 다이얼 값이 있고, 값이 2절 정의와 맞다. (DTF)
2. 인접한 화면끼리 골격이 다르다. 한 화면 안에 같은 모양 카드가 3개 이상 나란히 반복되지 않는다. (임의, SDE)
3. 한국어 제목 위에 영어 대문자 라벨이 0개다. (사용자)
4. 제목 밑 설명 문장, 조작 힌트, 범례 설명 문장이 없다. (사용자, DTF)
5. 큰 숫자에 단위가 붙어 있지 않다. 표 숫자 열은 `tabular-nums`에 오른쪽 정렬이다. (사용자, RDP)
6. 굵기 700 이상이 화면당 두세 곳 이하다. (임의)
7. 좌측 정렬선이 하나다. 나란한 요소들의 하단이 맞는다. (임의, RDP)
8. 넘치거나 잘린 요소가 없다 (가장 긴 문자열 기준). (사용자)
9. 사진이 옆 텍스트의 내용과 맞고, 한 화면에 같은 사진이 두 번 나오지 않는다. (사용자, CLAUDE.md)
10. 액센트 수가 design.md의 팔레트 구성과 맞다 (1: 하나, 3 듀오톤: 둘, 5 무액센트: 없음). 상태색 의미는
    고정, 회색 계열은 하나 (웜과 쿨을 섞지 않는다). (SDE, CLAUDE.md)
11. 아이콘은 Phosphor 한 패밀리, 굵기 규칙 하나. 이모지와 직접 그린 SVG가 없다. (CLAUDE.md, DTF, SDE)
12. 카피 존댓말 체계가 하나다 (해요체 또는 합니다체). 콘솔 라벨과 버튼은 명사형이다. (SDE, 해요체 허용은 임의)
13. 같은 의도의 버튼이 다른 이름으로 두 번 나오지 않는다. (DTF)
14. 빈 상태, 로딩, 에러 중 최소 하나가 설계되어 있다 (spec에 있는 것은 전부). (DTF, RDP)
15. 모든 모션에 한 문장짜리 이유가 있고, reduced motion에서 꺼진다. (DTF, CLAUDE.md)
