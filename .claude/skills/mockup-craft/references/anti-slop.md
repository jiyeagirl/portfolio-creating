# AI 티 목록

빌더가 피하고 리뷰어가 찾아내는 목록의 **유일한 원본**이다. `.claude/visual-review.md`도 이 파일을
기준으로 판정한다. 항목을 추가할 때는 여기에만 추가한다.

표시:
- **[사용자]**: 사용자가 직접 지우거나 고친 이력이 있는 항목. 가장 먼저 확인한다.
- 항목 끝의 괄호는 출처다. (SDE), (DTF), (RDP), (MIN), (HEV), (CLAUDE.md), (임의).
  약어 뜻은 `SKILL.md` "출처 표시"에 있다.

## 1. 카피

- **[사용자] 한국어 제목 위의 영어 대문자 라벨** (`OVERVIEW`, `LINEAGE`, `ITEM MAPPING`).
  - 화면당 0개. DTF의 "3섹션당 1개까지"보다 엄격하다.
  - `supanova-premium-aesthetic`과 `high-end-visual-design`은 제목 앞 대문자 필 배지를 의무화하지만,
    이 워크스페이스에서는 따르지 않는다.
  - 영어 라벨이 단독으로 쓰였다면 한국어로 바꾼다 (`원천 코드`, `변환 전 / 변환 후`).
  - 코드, ID, 기술 용어(API, DB, EA, SKU)는 예외다.
- **[사용자] 조작 힌트와 범례 설명 문장.**
  - 예: "행을 선택하면 산출 근거가 아래에 열립니다", "레드 막대는 기간 중 입고 최고치입니다",
    "좌우로 넘겨 필름을 골라보세요".
  - 꼭 필요하면 아이콘과 짧은 명사구로: "[차트 아이콘] 최근 12시간 시간대별 수집 건수".
- 제목을 다시 풀어 쓴 부제 ("~을 한눈에 확인하세요", "~를 스마트하게 관리하세요"). (DTF)
- 섹션 번호 라벨 (`01 / 기능`, `STEP 1`, `Phase 02`). 단계 표시는 단계 내용 자체가 라벨이다. (DTF)
- 시적이거나 귀여운 섹션명 ("오늘의 발견", "당신을 위한 순간"). 기능 이름을 쓴다: 최근 활동,
  예약 내역. (DTF)
- 금지 수식어. 구체적인 사실로 바꾼다 ("3분 만에 등록" 같은 것).
  - 혁신적인, 획기적인, 차세대, 원활한, 게임 체인저 (SDE)
  - 한 차원 높은 (SPA: supanova-premium-aesthetic)
  - 스마트한, 손쉽게, 한눈에, 효율적인, 최적의, 새로운 경험, 간편하게, 똑똑하게 (임의)
- 번역투 ("시작을 하세요 지금", "~하는 것이 가능합니다"). (SDE)
- 존댓말 체계 혼용. 반말과 존댓말을 섞지 않는다 (SDE).
  - 해요체(토스식) 또는 합니다체 중 하나로 고정한다. SDE는 합니다체만 허용하지만, 해요체도 허용한다.
    (임의)
  - 콘솔의 라벨과 버튼은 명사형이다 (저장, 반려, 등록일). (임의)
- 느낌표 성공 메시지, "앗!", "이런!" 에러. (RDP)
  - 담백하게 쓴다: "저장했습니다", "연결에 실패했습니다. 다시 시도해 주세요."
- 같은 의도의 버튼 이름이 둘 이상 (등록 / 추가 / 새로 만들기가 한 화면에). (DTF)
- 한 화면에 여러 말투가 섞임 (개발자 메트릭 문구, 에디토리얼 문장, 마케팅 문구). (DTF)
- 애매하면 귀여운 문장보다 **밋밋한 기능 문장**이 낫다. (DTF)

## 2. 목업 데이터

- Lorem Ipsum, 영문 placeholder 문장, "Coming Soon", TODO, 빈 섹션. (SDE, CLAUDE.md Completeness)
- 둥근 수 (`10,000원`, `50%`, `5.0`, `100건`) (SDE). 의미 없는 가짜 정밀도 (`99.99%`, `0.6 ctx/day`) (DTF).
- 합계가 안 맞음. 표 헤더의 "총 42건"과 실제 행, 페이지네이션이 서로 다름. (임의, DTF의 수치 신뢰성에서)
- 모든 행의 날짜가 같거나 시각이 전부 정각. (RDP)
- 같은 아바타, 같은 사진의 반복. (RDP)
- 흔한 이름을 쓰지 않는다.
  - 김철수, 홍길동, 이영희 금지. (SDE)
  - 외부 skill 예시 이름을 그대로 쓰는 것도 금지 (하윤서, 박도현, 이서진 등). SDE와 SPA는 이 이름을
    권장하지만 여러 프로젝트에 번지면 그것도 티가 난다. 프로젝트마다 새로 짓는다. (임의)
- 실존처럼 읽히는 가상 브랜드명 (넥서스, 스텔라랩스). 회사는 `A테크`, `B소재` 식이다. SDE는 고급스러운
  가상 브랜드명을 권장하지만 이 워크스페이스는 반대다. (CLAUDE.md)
- 레퍼런스 프로젝트의 사람과 시각을 그대로 가져오기 (`박채린`, `09:41`). (CLAUDE.md)

## 3. 레이아웃

- **같은 카드 3~4개를 나란히** 두는 구성. (SDE, DTF)
  - 콘솔에서는 KPI 카드 4개가 같은 문제다. (임의)
  - 대신 세로 헤어라인으로 구분한 한 줄 지표, 또는 핵심 지표 하나를 크게 두고 나머지를 작게 둔다.
    (DTF의 DENSITY 7 이상 규칙)
- 모든 것이 카드 안에 있음. 카드 안에 카드. (DTF, RDP)
- 모든 화면이 같은 골격: 섹션 제목, 더보기, 가로 스크롤 카드, 하단 탭바 (= A1). (CLAUDE.md)
- 행마다 위아래 테두리를 둘 다 둔다. 구분선은 한 방향만. (DTF)
- 장식용 그리드 선, 크로스헤어, 의미 없는 상태 점 (내비 항목마다 점). (DTF)
- 제목 오른쪽에 떠 있는 설명 문단. (DTF)
  - 오른쪽에는 **액션 버튼만** 둔다. (임의. DTF는 오른쪽 배치 자체를 금지하지만 콘솔 헤더 관례에 맞게 완화했다)
- 사진 위에 의미 없는 태그나 배지. 실제 상태(상영중, 품절)만 허용한다. (DTF)
- 사진 출처 캡션, 가짜 버전 표기, "마지막 동기화 4초 전" 같은 장식성 메타. (DTF)
- 스크롤 유도 표시, 날씨나 지역 시각 띠. (DTF)
- 빈 칸을 채우려고 넣은 타일 (항목 5개인데 6칸 그리드). (DTF)

## 4. 색과 표면

- 보라/파랑 "AI" 그라데이션, 네온 글로우. (SDE)
- 그라데이션 텍스트. SDE는 페이지당 1개를 허용하지만 여기서는 금지한다. (DTF)
- 여러 `radial-gradient`를 겹친 메시 배경, 블롭 배경. SDE는 권장하지만 여기서는 금지한다. (DTF)
  예외: CLAUDE.md 팔레트 6(라이브, 미디어 도메인의 비네트나 상태 글로우)은 기능이라 허용한다.
- 순수 `#000000` 텍스트나 배경. 채도 80% 이상의 액센트. (SDE)
- 웜 그레이와 쿨 그레이 혼용. (SDE)
- 섹션마다 라이트와 다크를 뒤집는 테마. (DTF)
  다크 사이드바와 라이트 본문 조합은 셸 선택이라 허용한다. (임의)
- 액센트 외의 색이 장식으로 등장 (로즈 액센트 앱의 청록 배지). (DTF)
- 큰 면적의 원색 배경. (MIN)
- 진한 검정 드롭 섀도 (`shadow-md`, `rgba(0,0,0,0.3)`). 그림자는 배경 색조로 옅게. (SDE, MIN)
- 모든 곳에 글래스모피즘. (DTF)
  화면 가장자리 바의 `backdrop-blur`는 CLAUDE.md가 금지한다. SDE의 Liquid Glass 권장은 따르지 않는다.
- 베이지, 브라스, 에스프레소 조합을 "고급스러움" 기본값으로 쓰기. (DTF)

상태 배지 참고 (MIN): 파스텔 배경에 짙은 글자, 채도는 낮게.
- 빨강 `#FDEBEC`/`#9F2F2D`
- 파랑 `#E1F3FE`/`#1F6C9F`
- 초록 `#EDF3EC`/`#346538`
- 노랑 `#FBF3DB`/`#956400`

그대로 복사하지 말고 프로젝트 팔레트에 맞춰 조정한다.

## 5. 사진

규칙은 CLAUDE.md Images 절이다: 고정 picsum id를 직접 보고 확인한 뒤 캡션 표에 기록한다.
반복된 실패:

- **[사용자]** picsum의 seed URL은 랜덤이라 내용과 맞지 않는다. 콘텐츠를 담는 사진은 id를 고정한다.
  SDE는 seed URL을 권장하지만 따르지 않는다.
- **[사용자]** 10장 이상을 한꺼번에 보고 나중에 표를 쓰면 id가 한 칸씩 밀린다. 한 장씩 확인하고 바로
  표에 적는다.
- 포스터, 상품, 장소처럼 **주제가 있는 사진은 주제 일치가 최우선**이다. (CLAUDE.md, DTF)
  실패 사례: 인물용 필름에 해파리 사진 (filmate 리뷰), 재활용 게시글에 사막 사진.
- **[사용자]** 맞는 사진이 없으면 비슷한 사진을 억지로 넣지 않는다. 그 자리는 임시로 톤 타일로 두고,
  최종 요약의 **사진 요청** 목록에 적어 사용자에게 받는다: 화면, 위치, 사진에 담겨야 할 내용, 비율과
  크기, 저장할 경로(`projects/<c>/<p>/assets/<이름>.jpg`). (CLAUDE.md Images 4번)
- 채도 과한 스톡 사진 (MIN), "다양한 팀원이 웃는" 스톡 사진 (RDP).
- pravatar 얼굴. SDE는 권장하지만 따르지 않는다. (임의)
