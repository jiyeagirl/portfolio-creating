# 고객용 반응형 웹 (web 프리셋)

쇼핑, 예약, 커뮤니티처럼 **고객이 쓰는 웹사이트**다. 관리자, 업무용 화면은 `console.md`,
iPhone 앱은 `app.md`다. 외부 skill의 랜딩, 사이트 규칙(SDE, DTF)이 이 플랫폼에서 가장 잘 맞는다.

- 출처 표시는 `SKILL.md` "출처 표시"를 따른다. **(임의)** 값은 결과를 보고 조정한다.
- 구조 선례는 `projects/community/locly` (`components/site/`). 구조와 완성도만 보고 수치와 색은
  새로 고른다 (CLAUDE.md 스케일 복제 금지). locly는 `<ResponsiveSite>`와 `?screen=` 이전에 만들어져
  둘 다 없고, 문구에 금지 문자(`·`, `—`)가 남아 있다. `src/index.tsx`와 카피는 따라 하지 않는다.

## 표시 방식

- **한 사이트가 데스크톱과 모바일 폭 모두에서 동작한다.** 모바일 전용 화면을 따로 만들지 않는다.
- `src/index.tsx`는 사이트를 `components/shared/responsive-site.tsx`의 `<ResponsiveSite>`로 감싼다.
  (CLAUDE.md "Responsive Web Output")
  - 기본 URL은 데스크톱 풀페이지(흰 배경)로 보인다.
  - `?view=mobile`이면 같은 사이트가 iPhone 프레임 안 393폭 iframe으로 보인다.
  - iframe이 자기 뷰포트를 가지므로 **일반 Tailwind 반응형(`sm:` `md:` `lg:`)을 그대로 쓴다.**
    container query나 `?view` 분기 코드를 쓰지 않는다.
- 시각 검증은 `npm run visual -- <c> <p> <화면...> --device=web`이다. 화면마다 `-desktop.png`(1440)와
  `-mobile.png`(프레임 안)를 모두 찍는다.

## 반응형 기준

- 기준 폭: 393 (모바일), 768, 1024 (태블릿), 1440 (데스크톱). 모바일 우선으로 작성한다.
  (locly spec의 대응 폭. 768은 임의)
- design.md에 **"반응형 기준"** 절을 둔다. 기기 프레임 절 대신이다.
  - 섹션마다 모바일에서 어떻게 접히는지 적는다: 몇 열에서 몇 열로, 무엇이 시트나 탭으로 가는지. (DTF)
- 페이지 가로 스크롤은 0이다. `npm run visual`이 데스크톱과 모바일 모두 검사한다. (SDE, DTF)
- 본문은 `mx-auto max-w-[...]`로 폭을 제한한다. 풀블리드는 의도한 섹션(히어로, 갤러리)만. (SDE)
  - 최대 폭 값은 프로젝트마다 새로 고른다. (CLAUDE.md)
- 화면 높이 단위는 `min-h-[100dvh]`를 쓴다. `h-screen`은 금지다. (SDE)
- 모바일 좌우 여백은 16 또는 24, 데스크톱 거터는 24 또는 32. 8px 그리드를 따른다. (임의, CLAUDE.md)
- 터치 타깃은 모바일 폭에서 44px 이상이다. (임의, HIG)

## 내비게이션

- 데스크톱 헤더는 한 줄에 둔다: 로고, 주요 메뉴, 검색, 계정. 줄바꿈되면 메뉴를 줄인다. (DTF)
- 모바일 헤더는 로고, 핵심 아이콘 두세 개, 메뉴 버튼으로 둔다. 메뉴는 시트나 전체 화면 패널이다. (임의)
- 모바일 하단 고정 CTA(예약하기, 장바구니)는 **불투명**이다. `backdrop-blur`와 반투명은 쓰지 않는다.
  (CLAUDE.md edge 규칙)
- 현재 위치는 메뉴 항목에서 굵기나 색으로 구분한다. (RDP)
- 푸터는 필수 링크, 사업자 정보, 고객센터만 둔다. 링크 4열 농장은 만들지 않는다. (SDE)

## 홈 골격

인접한 섹션은 서로 다른 레이아웃이어야 한다 (SDE, DTF). 아래 어휘에서 조합하고, 어느 것을 썼는지
design.md "아키타입" 절에 적는다 (앱의 A 번호 대신). 어휘 자체는 **(임의)**다.

- **히어로 (하나만)**
  - 좌정렬 분할: 텍스트 좌, 이미지 우. 모바일은 이미지 위, 텍스트 아래
  - 풀블리드 미디어: 이미지 위에 텍스트, 하단 그라데이션은 가독성용 기능
  - 검색 우선: 히어로 대신 큰 검색창과 조건 칩 (예약, 렌탈 도메인)
- **본문 블록**
  - 편집 그리드: 크기가 다른 이미지 카드 비대칭 배치
  - 가로 레일: 한 줄 스크롤 목록. 페이지당 한 번만
  - 조건 목록: 필터 칩과 결과 그리드
  - 이용 흐름: 3~4단계 숫자 없는 설명. 아이콘과 짧은 명사구
  - 신뢰 요소: 후기, 이용 수치, 운영 정보 중 도메인에 맞는 것 하나
- **금지**
  - 가운데 정렬 히어로 + 같은 카드 3열 + CTA 띠로 이어지는 템플릿 조합 (SDE, DTF)
  - 섹션마다 영어 아이브로우 (anti-slop.md 1절)
  - "이렇게 이용하세요" 식 설명 섹션을 여러 번 두기 (사용자)

## 커머스, 예약 화면 패턴

수치는 모두 (임의)다.

- **목록**
  - 데스크톱은 좌측 필터 + 결과 그리드 (3~4열)
  - 모바일은 상단 필터 버튼 → 바텀 시트 + 2열 그리드
  - 결과 수, 정렬, 선택된 필터 칩을 결과 위에 둔다. 결과 수는 실제 카드 수와 맞아야 한다.
  - 상품 카드: 이미지 비율 하나로 통일 (3:4 등), 이름 2줄 말줄임, 가격은 `tabular-nums`
    - 상태 배지(품절, 당일 가능)는 실제 상태만 표시한다. (DTF)
- **상세**
  - 데스크톱은 좌 갤러리, 우 정보 패널(sticky)
  - 모바일은 위 갤러리 → 정보 → 하단 고정 CTA
  - 가격, 옵션(사이즈, 색, 일정), 재고나 가능 여부를 CTA 바로 위에 모은다.
  - 사이즈나 실측 표는 표 규칙을 따른다: 숫자 오른쪽 정렬, 헤더에 단위 (console.md 표 절, 사용자)
- **예약, 결제**
  - 단계 표시는 단계 이름 자체가 라벨이다. "STEP 1" 금지 (DTF)
  - 금액 요약: 항목, 할인, 합계가 실제로 맞아야 한다. (DTF, 사용자)
  - 폼 라벨은 위, 에러는 아래에 둔다. (DTF)
- **상태 조회 (배송, 회수, 예약)**
  - 현재 단계가 가장 크게 보이게 한다.
  - 지난 단계는 시각과 함께 타임라인으로 둔다.
  - 예정 시각은 범위로 표시한다 (14:00~16:00).
- **마이페이지**: 목록 + 상세, 빈 상태는 한 줄 문구와 액션 하나 (DTF, RDP)

## 사진

- 상품, 착용, 장소처럼 **주제가 있는 사진이 화면의 절반 이상**이다. 주제 일치가 최우선이다.
  (CLAUDE.md Images)
- 한 상품의 갤러리 사진은 같은 상품처럼 보여야 한다. 모르는 사진 여러 장을 섞지 않는다.
- 맞는 사진이 없으면 톤 타일로 두고 **사진 요청 목록**에 올린다. (사용자, CLAUDE.md Images 4번)

## 모션 (출발점은 SKILL.md 2절 표: 홈 M5, 상세 M4, 목록과 예약 M3)

- 섹션 진입은 `IntersectionObserver`로 섹션당 1회만 한다. 스크롤마다 반복하지 않는다. (SDE, DTF)
- 이미지 hover 확대는 카드 이미지에만 쓰고, 데스크톱에서만 동작한다. (임의)
- 모바일 시트와 메뉴 패널은 SKILL.md 6절 표의 "시트, 패널, 드로어" 값을 쓴다.
- 캐러셀 자동 넘김은 쓰지 않는다. (임의)
