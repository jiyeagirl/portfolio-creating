# 웹 관리자 콘솔, 대시보드

외부 skill `design-taste-frontend`는 대시보드와 표를 범위 밖이라고 명시한다. 이 파일이 그 빈자리를
채운다.

- 셸 구조는 `ARCHETYPES.md` C1~C4와 `.claude/commands/scaffold.md` 3단계의 "웹 콘솔 구조 규약"을
  따른다. 치수는 셸마다 새로 고른다.
- 출처 표시는 `SKILL.md` "출처 표시"를 따른다. **(임의)** 값은 결과를 보고 조정한다.

## 밀도 (VISUAL_DENSITY 6~8)

- 카드 상자 대신 1px 선, 배경 톤, 여백으로 구분한다. (DTF)
  카드는 독립적으로 움직이는 단위(위젯, 차트 한 개)에만 쓴다.
- 블록 간 간격은 16 또는 24px, 표 셀 세로 패딩은 12 또는 16px에서 프로젝트마다 고른다. (임의, 8px 그리드)
- 숫자는 Pretendard에 `tabular-nums`를 쓴다. (RDP. DTF의 mono 숫자를 바꿈)
  mono 폰트는 코드, ID, 해시에만 쓴다. (scaffold.md 모노 유틸)

## 셸

- 좌측 사이드바가 기본값이 아니다. (RDP)
  - 프로젝트 성격에 따라 상단 커맨드 바(C3), 아이콘 레일과 섹션 리스트(C4)도 고른다.
  - 다크 레일(C1)은 이미 많이 쓰였다. (CLAUDE.md, ARCHETYPES.md)
- **[사용자]** 색 배치: 내비 면(사이드바, C3 상단 바, C4 아이콘 레일)만 브랜드 컬러의 짙은 면이고
  헤더와 본문은 흰색이다. 회색 캔버스를 깔지 않는다. 상세는 CLAUDE.md "관리자/콘솔 색 배치".
- 헤더에는 검색, 알림, 계정, 주 액션 하나를 둔다. 브레드크럼은 3단 이상일 때만 쓴다. (임의)
- 페이지 헤더는 좌측에 제목과 한 줄 메타, 우측에 액션 버튼을 둔다. 우측에 설명 문단을 두지 않는다.
  (DTF)

## 지표

- **[사용자]** 단위는 라벨로 옮긴다: `정산 대상 건수 (건)`, `정산 금액 (원)`.
  - 숫자는 600 안팎, 자간은 기본에 가깝게 둔다.
  - 굵고 촘촘한 큰 숫자에 단위가 붙은 모양은 외부에서 "AI가 만든 대시보드"로 지적받았다.
- 같은 모양 KPI 카드 4개를 나란히 두지 않는다 (임의. SDE와 DTF의 "같은 카드 3개 금지"를 콘솔에
  적용). 대안:
  - 세로 헤어라인으로 구분한 한 줄 지표 (카드 없음) (DTF)
  - 핵심 지표 하나를 크게 두고 보조 지표를 작게
  - 지표와 스파크라인을 표의 첫 행처럼 배치
- 증감은 색과 부호로 표시한다 (`+2.4%`). 화살표 아이콘을 모든 지표에 붙이지 않는다. (임의)

## 표

- 8~15행을 보여주고 페이지네이션을 둔다. (임의)
  헤더의 총 건수, 필터 결과, 페이지 정보가 서로 맞아야 한다.
- 열은 6개 이하로 둔다. 넘치면 보조 정보를 이름 아래 두 번째 줄로 내리고 열을 줄인다.
  (scaffold.md 4단계)
  - `overflow-x-auto` 안에서 폭이 넘치면 마지막 열이 조용히 잘린다. design.md 컬럼 예산에 기록한다.
- 숫자 열은 오른쪽 정렬과 `tabular-nums`, 헤더에 단위를 쓴다. 텍스트 열은 왼쪽 정렬이다.
  (RDP, 사용자)
- 구분선은 행 아래 한 줄만 둔다. 줄무늬(zebra)와 위아래 테두리를 같이 쓰지 않는다. (DTF)
- 행 hover는 배경 틴트로 한다. 확대(scale)하지 않는다. (임의. SDE의 hover 확대를 뒤집음)
- 행 상세는 모달보다 우측 슬라이드오버나 master-detail 패널로 연다. (RDP)
- **[사용자] 골프장, 회사, 상품 같은 고유명은 이름 중간에서 줄바꿈하지 않는다.** 목록으로 나열할 때는 이름마다 `whitespace-nowrap` 요소로 감싸 이름 단위로만 줄이 바뀌게 한다 (`가온 파크 CC`가 `가온 파크` / `CC`로 쪼개지면 안 된다). `join(", ")`으로 한 문자열을 만들면 이름 안의 공백에서 끊긴다.
- 긴 이름 셀은 `min-w-0 truncate`로 하고, 전체 이름은 `title` 속성이나 상세에서 보여준다.
  (사용자, 넘침 규칙)
- 표 위에는 필터, 탭, 검색을 둔다. "행을 클릭하면 상세가 열립니다" 같은 안내 문구는 쓰지 않는다.
  (사용자)

## 상태 배지

- 5단계 톤 구조(대기, 진행, 조치 필요, 완료, 중단)를 프로젝트 안에서 고정한다. (scaffold.md)
- 파스텔 배경에 짙은 글자를 쓴다 (MIN). 대문자 변환은 하지 않는다. 글자 크기는 표 본문보다 한 단계
  작게 한다. (임의)
- **[사용자] 상태 칩은 글자 수와 상관없이 크기를 고정하고 글자는 가운데 정렬한다.** 같은 규격을 화면 전체에서 반복해 쓰는 것이 웹 UI의 기본이다. 가장 긴 라벨에 폭을 맞추되 옆으로 넓어지지 않게 라벨을 줄인다 (`보안인증 필요`는 `인증 필요`). 앱 화면의 칩도 같다.
- 상태 점은 상태 셀 안에서만 쓴다. 내비 항목이나 모든 행 앞에 장식 점을 찍지 않는다. (DTF)
- "NEW", "HOT", "BETA"처럼 정보 없는 배지를 모든 행에 붙이지 않는다. (RDP)

## 버튼과 폼

- 한 영역에 채움 버튼 하나와 고스트 버튼을 두고, 그 외는 텍스트 링크로 한다. (RDP)
- 라벨은 2~6자 명사나 동사로 쓴다 (저장, 승인, 반려, 내보내기). 줄바꿈되면 라벨을 줄인다.
  (임의. DTF의 "버튼 줄바꿈 금지"에서)
- 높이는 36~40px, 모서리는 프로젝트 radius 규칙을 따른다. (임의)
  hover는 배경 톤으로, focus ring은 반드시 둔다. (MIN, RDP, SDE)
- 폼 라벨은 위, 에러는 아래, 필수 표시는 라벨 옆에 둔다. placeholder를 라벨 대신 쓰지 않는다. (DTF)
- 파괴적 행동(삭제, 반려)은 확인 단계가 있다. (임의)

## 차트

- 라이브러리 없이 직접 구현한다. (scaffold.md 워크스페이스 관례)
- 범례와 축 라벨은 짧게 쓴다. 차트 해설 문장을 차트 아래에 쓰지 않는다. (사용자)
- 강조 색은 한 계열만, 나머지는 회색 톤으로 한다. 막대마다 다른 색을 쓰지 않는다. (SDE 액센트 1개)
- 진행 막대는 4~6px 두께로, 사용률이나 할당량처럼 의미 있는 곳에만 쓴다. (임의. DTF에서 변형)

## 상태 화면

- 빈 목록은 한 줄 문구와 주 액션으로 한다: "등록된 자산이 없습니다" + [자산 등록]. (DTF, RDP)
- 빈 대시보드는 시작하기 체크리스트처럼 구성된 화면으로 만든다. (RDP)
- 마지막 동기화 시각은 실제 기능일 때 한 곳에만 둔다. (DTF에서 완화)

## 모션 (MOTION 2~3 기준)

- 드로어, 슬라이드오버, 드롭다운, 토스트 등장 정도만 움직인다. 시간은 SKILL.md 6절 표의 콘솔 값
  (180~280ms)을 쓴다. (임의)
- 표 행, 카드, 지표를 하나씩 등장시키지 않는다. 숫자 카운트업도 쓰지 않는다.
  (임의. SDE의 카운트업 지표를 뒤집음)
